# 미결정 사항과 담당자 후속 작업

사용자의 순차 답변을 일괄 반영했다. 확정 정책은 요구사항·도메인 문서를 기준으로 하며, 아래에서 보류와 담당자 후속 작업을 구분한다. 담당자가 운영 수치를 수정하는 일을 정책 자체의 미결정으로 해석하지 않는다.

## 게임

- [확정] 최소 보상 점수는 [게임 보상 규칙](../02-domain/game.md#보상-지급)을 따른다(2026-10-12 사용자 결정). FE 기준 안내·미달 결과 표시와 BE 자격 검사·지급 연결은 구현 후속이다. 타꼬런의 상세 검증 계약은 별도로 확정한다.

- [확정] 글자색깔 맞추기의 점수·목숨·제한 시간·종료 조건은 [게임 규칙](../02-domain/game.md#글자색깔-맞추기-규칙)을 따른다. 2026-10-12 담당자가 현재 규칙을 채택했다.
- [담당자 확정 후 공유] 그 외 제공할 게임 종류·규칙은 게임 담당자가 결정한다. 타코야끼 만들기는 후보이며 확정 게임이 아니다.
- [확정] 2026-10-12 사용자가 명세 우선 및 추천안 적용을 확인했다. 글자색깔 맞추기는 seed 기반 문제 재현·일괄 답변 제출, 일시정지 유지·시간 경계·중도 종료·결과 확정 시각의 KST 보상일과 공개 DTO를 [색깔 게임 연동 계약](../05-api/game-color-word-draft.md)에 따라 구현한다. 클라이언트 기록의 신뢰 한계도 유지한다.
- [구현 후속] 색깔 게임의 입력 처리·보존 한도, 공개 오류 번호·소유권 은닉·차단 기록 연동, 실제 FE 반영 및 Java/TypeScript 생성기 일치 검증. 결정된 계약과 구현·통합 검증 완료는 구분한다.
- [담당자 설계 후 공유] 서버 판정 원칙을 유지하고 다른 게임의 유효성 검증 방식을 설계한다. 담당: 전민규.
- [검토 대기] 프론트에 구현된 타꼬 타이밍 맞추기·타꼬 주문은 도메인 규칙에 아직 없다. 두 게임의 플레이 규칙과 최소 보상 점수를 확정한다. 타이밍은 50점 임시 제안(테스트 플레이 후 조정), 주문은 아직 구현 단계라 규칙 확정 후 결정(현재 규칙 참고값 18점). 초안: [타꼬 타이밍](../05-api/game-takko-timing-draft.md), [타꼬 주문](../05-api/game-takko-order-draft.md).
- [선택 완료 — 2026-10-16] 타꼬런은 FE A안·고정120Hz·xorshift32·endTick/type으로 BE를 맞춘다. 추가 질문에서 활성10분 정상 종료와 서버 경과시간 대조 후속을 선택했다. [타꼬런 계약](../05-api/game-takko-run-draft.md)을 따르며 실제 FE 변경·Java/TS 교차 검증·운영 반영은 후속이다. 타이밍·주문의 규칙·보상은 별도 미확정 상태를 유지한다.
- 보상 초기화 시간과 동일 플레이 재시도는 [게임 규칙](../02-domain/game.md)으로 확정했다.

## 응모와 어뷰징

- [확정 정책의 담당자 관리·수정] 사용자별 빈도·비정상 요청 반복 탐지, 출석·미션·게임 지급 단계 탐지 및 사용자별 요청 빈도 제한을 적용한다. 세부 조건·시간·횟수는 담당자가 관리·수정한다. 담당: 석종수, 게임별 검증 연계: 전민규.
- 위 항목은 적용 여부가 미정인 기능이 아니다. 기준은 [응모·어뷰징 규칙](../02-domain/entry.md)을 따른다.

## 추첨과 결과 발표

- [결정 완료 — 2026-10-14] 자동 추첨은 마감 +5분 기준을 유지하고, 최초 공개는 관리자 육안 검토 후 발표 요청 한 번으로 최종 확인 기록과 공개를 함께 처리한다. 화면은 결과 발표 대기이며 카운트다운·고정 발표 예정 시각을 제공하지 않는다. 기준은 [추첨 규칙](../02-domain/drawing.md#결과-발표)과 [ADR-022](../03-decisions/022-manual-initial-publication.md)이다. 장애·정합성 오류의 나머지 복구 및 취소 전환 기준은 후속으로 유지한다.
- [결정 완료 — 2026-10-15] `POST /api/v1/admin/draws/{runId}/result-confirmation`을 정상 최초 INITIAL 결과까지 확장해 발표 요청 한 번으로 최종 확인·공개한다. 최초 공개 전 취소·재추첨이 있으면 유지 당첨자와 최종 재추첨 결과를 합친 전체 명단을 처리하며 실행 하나의 명단만 부분 공개하지 않는다. 기존 `POST /api/v1/admin/draws/{runId}/publication`은 최초 공개 후 재추첨 명단 갱신 용도로 유지하고 최초 발표 전에 연달아 호출하지 않는다. 검토 중 명단이 변경되면 이전 화면의 발표 요청을 거절하고 최신 명단을 다시 확인하도록 안내한다. 동일 발표 요청 재시도는 기존 성공 결과를 반환하며 공개 버전·알림을 중복 생성하지 않는다. 명단 변경 요청과 동일 처리 재시도를 구분한다. 활성 관리자라면 발표할 수 있고 실제 발표자·시각을 기록한다.
- [이번 구현 제외·운영 확대 시 후속] 발표 후 취소·재추첨을 이번 운영에서 사용하지 않는 전제로, 공개 화면의 취소자 임시 표시·본인 중간 결과는 GD-140에서 구현하지 않는다. 기존 관리자 정책·API는 유지하며 해당 운영을 시작하기 전에 표시 계약을 보완한다. 관리자 결과의 공개 이력·당첨 취소 여부 분리와는 별개다.
- [선택적 연계 후속] 취소 요청의 abuseCaseId와 어뷰징 판단 근거 연결 방식. 관리자 사유에 따른 개별 당첨 취소·빈 자리 재추첨은 확정했으며 어뷰징·자격 미달 확인이나 기록 연결을 필수로 요구하지 않는다.
- [제공 방향 확정·현행 구현 대조] 관리자 상세의 `execution` 요약과 전체 실패·업무별 실행 감사 이력의 페이징 경로·응답을 [추첨 API](../05-api/drawing.md#관리자-운영-이력--현행-구현)에 기록했다. 공통 감사 조회 API 제외는 [원격 확정 감사 명세](https://github.com/Uplus-GETDDO/getddo-spec/blob/32e105545a389fffdc843bf1d11f8d7129163a14/05-api/audit.md)를 따른다. 실제 시작·재개 처리자와 취소 처리자를 구분하며 취소 기록으로 실행 행위를 대신하지 않는다. FE 연동 완료는 별도 확인한다.

- [결정 완료 — 2026-10-14] 이름·전화번호 표시 규칙과 이메일 제외는 [결과 발표](../02-domain/drawing.md#결과-발표)에 반영했다. 사용자 결과 조회 E08·E09 초안은 채택했으며 미등록 값의 별도 대체 표시는 이번 범위에서 다루지 않는다.
- [세부 처리 미확정] 추첨 자료의 운영상 보관은 마지막 결과 공개·취소 후 5년(추후 수정 가능)이다. 탈퇴 기능은 제외했다. 개인정보 파기 시 익명화·집계 보존 방식은 사용자가 선택하지 않았으므로 임의로 확정하지 않는다. 운영상 5년을 개인정보의 일괄 법정 보존 근거로 해석하지 않는다.

## 배너

- [확정 · 담당자 연동 후속] 이벤트 ID·순서1~5와 삽입/삭제 정리·삭제/취소 사용자 숨김과 관리자 보존·이미지 주소 분리·감사 추적은 [배너 규칙](../02-domain/banner.md)을 따른다. 실제 이미지 기반·기존 행·FE 연동은 별도 확인한다.

- [담당자 추후 확정] 이미지 허용 형식·파일당 용량 제한. JPG·PNG·WebP 및 5MB 등 제안 수치는 채택하지 않았다.

## 원문에서 확인되지 않은 항목 — 보류

- [보류] 변경 이력에는 운영 및 시연 15절, 공통 추가 검토 16절, 비기능 요구사항이 언급돼 있지만 전달된 최종 본문에는 해당 절이 포함돼 있지 않다. 원문 확인 항목을 유지한다.
- 배너 이미지 기준은 원문 확인과 별개로 담당자가 확정한다.

## 사용자 문맥과 알림 API

- [결정 완료 · 프론트 반영 후속] 사용자 문맥 헤더는 `X-User-Role`을 받아 DB와 대조하고, 권한은 DB 역할로만 판단한다. 백엔드 구현과 일치하도록 공통 계약과 알림 명세를 정렬했다([작업 기록](../04-worklogs/2026-10-12-user-context-header-decision.md)). 프론트엔드의 역할 헤더 전송은 후속 작업이다. 공통 처리 위치는 백엔드 `CurrentUserArgumentResolver`가 담당한다. 사용자 전달에 따르면 이경주 담당자가 해결할 예정이며, 구체적인 연결 방식과 완료 여부는 아직 확인되지 않았다. 사용자·역할·멤버십 및 공통 사용자 처리는 이경주, 알림 소유권 검증·조회·읽음 처리는 전민규 담당 영역이다.
- [세부 계약 미확정] `INACTIVE` 사용자 처리와 테스트 사용자 목록·시드 제공 방식은 [공통 사용자 문맥](../05-api/common.md#시연용-사용자-헤더--사용자-요청을-반영한-권고안)의 후속 확인 항목이다. 이번 N01~N03 확정으로 임의로 결정하지 않는다.
- [확정 범위] [N01~N03 요청·응답·오류 계약](../05-api/notification.md#사용자-알림--n01n03-확정)은 2026-09-30 확정했다. 공통 API 전체와 관리자 알림 AN01~AN05는 이 N01~N03 확정 범위에 포함하지 않는다. 관리자 AN01~AN05는 2026-10-12 별도 사용자 확인으로 [관리자 알림 계약](../05-api/notification.md#관리자-알림-운영--an01an05-확정)을 확정했다.

## 등급 응모권

- [확정] 게임·미션 보상은 등급 응모권 1장을 무작위 지급한다. 확률·장당 가중치와 중복 방지는 [응모권 규칙](../02-domain/ticket.md#게임미션-보상의-등급-추첨)을 따른다.
- [확정] 기본·연속 출석 보상은 브론즈 응모권으로 고정 지급한다. 지급 수량과 장당 가중치는 [출석 규칙](../02-domain/attendance.md)을 따른다. 게임·미션의 무작위 지급 정책은 출석에 적용하지 않는다.
- [확정 · 2026-10-17] 플래티넘(`PLATINUM`) 추가와 확률·장당 가중치 변경은 [응모권 규칙](../02-domain/ticket.md#게임미션-보상의-등급-추첨)을 따른다. 플래티넘의 서비스 적용 시점과 지급·잔액·응모·추첨·화면 연동 검증은 담당자 후속으로 남긴다.
- [미결정] 기존 무등급 보유 응모권 및 운영 중인 미션·보상 정책의 전환·적용 시점. 기존 지급·응모·추첨 이력을 소급 재추첨하거나 덮어쓰지 않는다.
- [확정] 응모 시 사용자가 등급별로 쓸 장수를 고르고, 같은 등급 안에서는 만료가 이른 응모권부터 차감한다. [응모권 규칙](../02-domain/ticket.md#응모권-경제운영)을 따른다.
- [확정] 응모 요청은 등급별 장수 맵(`tickets`)이고 응답에 등급별 차감 장수를 포함한다. 가중치 미적용 이벤트는 브론즈 응모권만 쓸 수 있다. [응모 API](../05-api/entry.md#응모-요청응답)를 따른다. 프론트엔드에 공유해 화면 반영을 확인한다.
- [확정] 이벤트 취소로 반환되는 응모권은 같은 응모권이 등급 그대로 사용 가능 상태로 돌아온다. 반환분의 유효기간은 [응모권 규칙](../02-domain/ticket.md)을 따른다.
- [담당자 후속] 윤태형: 등급별 지급·잔액·차감·반환 모델과 게임·미션이 사용할 지급 계약. 석종수: 등급별 추첨 가중치·후보 스냅샷. 전민규: 게임 보상 자격·지급 기능 연동, 관리자 조회·보상 표시. 공개 API 필드와 ERD는 담당자 검토 후 반영한다.
- [범위] 확률·가중치의 관리자 설정 기능, 확률 변경 적용 시점과 이력 관리 기능은 이번 요청만으로 추가하지 않는다.

## 지급 전 차단 전환의 후속 확인

- [후속 확인] 지급 전 차단을 게임에만 적용할지, 출석·미션에도 적용할지. 기존 출석·미션·게임 탐지 및 요청 빈도 제한의 적용은 유지하며 탐지 적용을 새 차단 범위 확정으로 해석하지 않는다.
- [후속 확인] 명확한 규칙 위반과 어뷰징 의심을 어떤 기준으로 차단할지. 기존의 서버 무효 판정과 의심만으로 유효 점수·보상을 보류하지 않는 원칙을 임의로 변경하지 않는다.
- [후속 확인] 지급 후 발견한 부정의 게임 점수 무효화와 판단 근거·이력 계약의 변경 여부. 결정 전까지 기존 점수 처리 정책을 유지한다. 관리자 개별 당첨 취소·빈 자리 재추첨의 제공 여부는 아래와 같이 확정했다.
- [결정 완료 — 2026-10-14] 마감 +5분 자동 추첨은 유지한다. 자동 발표는 관리자 수동 공개로 대체하며 고정된 발표 시각은 제공하지 않는다.
- [담당 영역 후속] `02-domain/notification.md`, `05-api/notification.md`는 사용자 요청에 따라 이번 변경에서 제외했다. 신규 제외 알림 발생 정책과 기존 `ENTRY_EXCLUDED`·과거 알림 호환성은 알림 담당자가 별도로 검토해야 한다. 해당 문서의 제외 알림 기술을 신규 추첨 제외 기능 유지 근거로 해석하지 않는다.

## 관리자 당첨 취소·재추첨 — 확정 범위와 추후 추가 예정

- [확정] 관리자는 취소 사유를 기록하여 개별 당첨을 취소하고 빈 자리만 재추첨할 수 있다. 어뷰징·자격 미달 확인을 필수 조건으로 요구하지 않는다. 당첨 취소·재추첨을 이유로 응모권을 반환하거나 회수하지 않는다. 취소 대상이 아닌 당첨자·경품·최초 가중치는 유지한다.
- [추후 추가 예정 · 이번 구현 제외] 전체 당첨자를 취소하고 처음부터 다시 추첨하는 기능. 후보·가중치·과거 당첨자 자격·공개 전환·중복 처리·이력 관계는 아직 확정하지 않는다.
- [상세 계약 후속] 관리자 권한·사유 입력 검증·업무 오류·선택적 어뷰징 근거 연계는 구현 전 확인한다. 상세 API 계약 전체를 이번 정책 확인만으로 확정하지 않는다.
- 기준: [추첨 규칙](../02-domain/drawing.md#재추첨), [ADR-019](../03-decisions/019-admin-award-cancellation-and-partial-redraw.md).

- 발표 대기 문구와 고정 예정 시각 없음은 2026-10-14 결정으로 정리했다. 장애·정합성 오류 복구·어뷰징의 다른 후속 항목은 유지한다.
