# 기능 요구사항

- 확정된 요구사항은 서술형으로 작성한다.
- 아직 정하지 않은 정책은 [미결정 사항](pending-decisions.md)에 기록한다.
- 구체적인 수치와 운영 기준이 확정되지 않은 항목은 임의로 확정하지 않는다.

## 공통 시간 기준과 화면 표시

- 서버의 현재 시각, 시각 데이터 저장 및 시간 비교는 UTC를 기준으로 한다.
- 사용자 화면과 관리자 화면의 모든 시각은 KST(Asia/Seoul, UTC+09:00)로 변환해 표시한다. 이벤트·미션 운영 기간, 응모권 만료 시각, 출석·보상·알림·추첨·관리 이력에 동일하게 적용한다.
- 관리자가 화면에서 입력하는 운영 시작·종료 시각 등은 KST로 해석하고, 서버에서는 같은 순간의 UTC 시각으로 변환해 저장·처리한다. 화면에는 한국 시간 기준임을 안내한다.
- API로 주고받는 시각은 UTC 또는 오프셋을 명시해 시간대가 모호하지 않게 한다. 서버가 제공한 기준 시각으로 기간·만료·발표 여부를 판단하며 클라이언트 기기 시각을 판정 기준으로 사용하지 않는다.
- 업무 기준일·기준월은 KST(Asia/Seoul)로 판단한다. 일일 출석·게임 보상은 매일 한국 시간 00:00에, 연속 출석 월간 상태는 매월 1일 한국 시간 00:00에 초기화한다. 응모권의 귀속월·만료와 정책 적용일도 KST 날짜·월 경계를 따른다. 한국 시간 00:00은 UTC로 전날 15:00이며, 서버는 이 순간을 UTC로 저장·비교한다.
- 출석 인정일·보상 기준일·기준월은 서버 시각을 Asia/Seoul로 변환한 날짜·월로 산출한다. 이 업무 날짜는 KST 기준으로 저장하며, 실제 발생 시각을 저장하는 UTC 타임스탬프와 구분한다. 예를 들어 9월 22일 15:30 UTC의 출석은 한국 시간 9월 23일 00:30이므로 9월 23일 출석이다.
- 마감 후 5분 발표와 시작 10분 전 알림의 간격은 시간대 변환에 따라 달라지지 않는다. 카운트다운은 서버 기준 예정 시각으로 계산한다.

## 1. 이벤트 관리

### 이벤트 등록 및 관리

- 이벤트 이름, 설명, 이미지, 응모 기간을 관리한다.
- 여러 이벤트를 개설할 수 있으며, 이벤트 등록과 동시에 경품 및 당첨 인원을 등록한다. 이벤트와 경품 등록은 함께 성공하거나 함께 실패하며, 경품 없이 이벤트만 등록 완료하지 않는다.
- 동일 이벤트의 등수마다 한 종류의 경품만 등록할 수 있다. 같은 등수에 서로 다른 종류의 경품을 함께 등록할 수 없으며, 해당 경품의 당첨 인원은 별도로 설정한다.
- 이벤트는 응모권 미사용 이벤트와 응모권 사용 이벤트로 구분한다.
- 응모권 미사용 이벤트의 필요 응모권 수는 0장이다.
- 이벤트별 최소 유플러스 멤버십 등급을 설정하며, 해당 등급 이상인 사용자에게 응모를 허용한다.
- 등급 순서는 우수 < VIP < VVIP다. 최소 등급이 VIP이면 VIP와 VVIP가 응모할 수 있으며, 등급별 개별 선택 방식은 사용하지 않는다.
- 관리자는 응모할 수 없다. 임직원 여부는 별도로 구분하거나 응모 제한 조건으로 사용하지 않는다.

### 응모권 미사용 이벤트

- 응모권 차감 없이 이벤트에 응모한다.
- 원하는 경품을 선택하지 않고 이벤트 자체에 응모한다.
- 등수별 경품과 당첨 인원을 설정한다. 예: 1등 1명, 2등 5명, 3등 20명.
- 단일 경품에 당첨 인원을 설정한다. 예: 동일 경품의 당첨자 1명 또는 50명.

### 응모권 사용 이벤트

- 지정된 시각에 모집을 시작하고 정해진 시간 동안 응모를 접수한다.
- 이벤트 하나당 모집 회차는 하나이며, 모집 마감 후 해당 이벤트의 유효 응모자를 대상으로 추첨한다.
- 모집 시간은 이벤트별로 설정한다. 15시부터 15시 10분까지 모집하는 것은 예시이며, 10분으로 고정하지 않는다.
- 일반 가중치 적용 이벤트는 사용자당 해당 이벤트에서 추가 응모를 포함해 응모권을 누적 최대 5장까지 사용할 수 있다. 1회 요청당 제한이 아니라 이벤트별 사용자 누적 사용 상한이다. 월말 소진용 이벤트의 상한 없음 예외는 [응모권 규칙](../02-domain/ticket.md)을 따른다.
- 가중치 미적용 이벤트는 응모권 1장을 차감해 응모하며, 응모자에게 동일한 추첨 가중치를 적용한다.
- 다음 두 가지 경품 구성에 대한 추첨을 지원한다.
  1. 단일 경품을 대상으로 추첨한다.
  2. 여러 경품을 대상으로 등수별로 추첨한다.

이벤트의 수정·삭제 제한과 상태 규칙은 [이벤트 도메인 규칙](../02-domain/event.md)을 따른다.

## 2. 출석

### 기본 출석

- 출석은 이벤트별이 아닌 사용자 단위로 관리한다.
- 일일 출석 보상의 초기 설정은 응모권 1장이다. 관리자가 변경한 수량은 다음 일일 기준일부터 적용한다.
- 동일한 일일 출석에 대한 중복 지급을 방지한다.
- 버튼 연타·새로고침·동시 요청·날짜 변경 경계에서도 같은 출석은 한 번만 반영한다.
- 출석 기록과 응모권 지급 결과의 일치를 보장한다.
- 별도 출석 동작으로 출석을 인정한다.
- 사용자별 출석 가능 횟수는 매일 00:00 KST(Asia/Seoul)에 초기화한다. 서버에서는 해당 시각을 UTC로 변환해 처리한다.

### 연속 출석

- 연속 출석은 매월 초기화되며 같은 달 안에서 달성 여부를 판정한다.
- 연속 출석 일수는 매월 1일 00:00 KST에 0으로 초기화하며, 출석하지 않은 날이 있으면 0으로 돌아간다.
- 단계별 달성 일수와 보상 응모권 수를 관리한다.
- 상위 단계 달성은 하위 단계 보상을 대체하지 않으며, 같은 달에 같은 단계의 보상은 한 번만 지급한다.

초기 단계 설정은 다음과 같다. 단계 일수·수량 변경은 다음 달부터 적용한다.

| 단계 | 달성 조건 | 보상 |
| --- | --- | --- |
| 1단계 | 같은 달에 7일 연속 출석 | 응모권 1장 |
| 2단계 | 같은 달에 14일 연속 출석 | 응모권 3장 |
| 3단계 | 같은 달에 28일 연속 출석 | 응모권 7장 |

출석 인정과 연속 출석 판정 기준은 [출석 도메인 규칙](../02-domain/attendance.md)을 따른다.

## 3. 서비스 공통 미션

- 미션은 특정 이벤트에 속하지 않는 서비스 공통 퀴즈·설문이다.
- 관리자가 매번 새 미션과 문항을 수동 등록한다. 자동 반복·같은 미션 재달성은 제공하지 않는다.
- 사용자당 미션별 달성·보상은 1회이며, 새로 등록된 다른 미션은 별도로 달성할 수 있다.
- 미션별 운영 기간, 내용과 완료 조건을 설정한다. 완료 보상은 [응모권 등급 추첨 규칙](../02-domain/ticket.md#게임미션-보상의-등급-추첨)에 따라 등급 응모권 1장을 지급한다.
- 설문은 모든 필수 문항에 답변해 최종 제출한 경우 서버가 완료를 판정하고 즉시 보상한다.
- 퀴즈는 정답일 때만 완료·보상을 인정한다. 오답 재도전은 운영 기간 안에서 무제한이며, 요청 빈도 제한은 별도로 적용한다.
- 시작 시각 이상·종료 시각 미만에 서버가 받은 제출을 인정하며, 검증 완료가 종료 후여도 기간 내 제출이면 완료 조건에 따라 보상한다.
- 재제출·통신 재시도·동시 요청으로 같은 사용자·미션의 달성·보상이 중복되지 않도록 한다.

출석과 게임은 미션으로 관리하지 않는다. 상세 기준은 [미션 도메인 규칙](../02-domain/mission.md)을 따른다.

## 4. 게임

- 여러 종류의 게임을 제공한다.
- 게임은 순환 방식이 아닌 전체 게임을 한 번에 공개한다.
- 게임별 점수를 기록하며 개인 최고점과 누적 점수를 보관한다.
- 게임 점수는 서버가 판정한다.
- 게임은 횟수 제한 없이 플레이할 수 있다.
- 게임 보상은 사용자별로 각 게임에서 하루 1회 등급 응모권 1장을 지급한다. 같은 날 서로 다른 게임의 보상은 각각 받을 수 있다.
- 게임 보상은 유효로 판정한 플레이가 있을 때 지급하며, 점수나 플레이 횟수에 따른 차등 지급은 하지 않는다.
- 같은 게임의 반복 플레이나 보상 정책 변경으로 동일 보상 기준일의 지급 제한이 초기화되지 않는다.
- 게임 보상은 매일 00:00 KST(Asia/Seoul)에 초기화한다.
- 서버 발급 플레이 ID의 재제출에는 최초 확정 결과를 반환하고 점수·횟수·보상을 중복 반영하지 않는다.
- 어뷰징 의심 건은 관리자 검토 후 조치하며 세부 기준은 담당자가 관리·수정한다.

게임 결과 판정과 보상 지급 기준은 [게임 도메인 규칙](../02-domain/game.md)을 따른다.

## 5. 응모권

- 기본 출석, 미션, 게임 보상으로 응모권을 지급한다.
- 기본 출석 보상의 초기 설정은 일일 1장이다. 정책 변경은 출석 규칙을 따른다.
- 보유 응모권 수와 지급·차감 이력을 조회한다. 게임·미션의 무작위 등급, 지급 장수와 등급별 가중치는 [응모권 규칙](../02-domain/ticket.md#게임미션-보상의-등급-추첨)을 따른다. 실제 장수와 추첨 가중치를 구분해 표시한다.
- 이력에서 수량, 사유, 발생 시각, 관련 행위를 확인한다.
- 포인트는 사용하지 않고 응모권으로 관리한다.

응모권의 정합성·반환·만료 규칙은 [응모권 도메인 규칙](../02-domain/ticket.md)을 따른다.

## 6. 이벤트 응모

- 이벤트 목록과 상세 정보를 조회한다.
- 응모 기간, 경품, 응모권 차감 여부, 최소 허용 멤버십 등급, 추첨 방식, 가중치 규칙을 확인한다.
- 응모권 미사용 이벤트는 경품을 선택하지 않고 이벤트에 응모하며 응모권을 차감하지 않는다.
- 응모권 사용 이벤트는 모집 시간 내에 응모권을 차감해 응모한다.
- 내 응모 내역에서 이벤트, 응모에 차감한 응모권 수, 처리 시각, 결과, 거절 사유를 확인한다.
- 사용자의 응모 취소는 제공하지 않는다.

응모 횟수·중복 방지·마감 판정은 [응모 도메인 규칙](../02-domain/entry.md)을 따른다.

## 7. 실시간 응모 현황

- 응모자 수를 표시한다. 응모자 수는 사용자 중복을 제거한 인원이다.
- 추가 응모를 포함한 접수 건수는 응모 건수로 구분한다. 별도 표시 여부는 구현 범위에 따라 정한다.
- 응모권 사용 이벤트에서는 총 응모에 차감한 응모권 수와 본인의 응모에 차감한 응모권 수를 표시한다.
- 원본 기록과 집계 결과의 일치를 보장한다.
- 당첨 확률은 표시하지 않는다.
- 현황을 자동 갱신하며, 응모 직후 결과를 바로 반영한다.
- 갱신 주기는 구현 담당자가 정한다.

## 8. 어뷰징 탐지 및 관리자 검토

- 비정상 반복 응모를 탐지하고 사용자·이벤트·탐지 사유·발생 시각·관련 요청을 기록한다.
- 탐지 사실만으로 자동 제외하지 않는다.
- 이벤트 응모 검토와 응모권 지급 검토를 구분한다. 부정 지급 검토는 이벤트 응모 전에도 가능하다.
- 관리자는 참여 허용 또는 해당 이벤트의 추첨 대상 제외를 결정한다.
- '참여 허용'은 관리자 검토 결과이며, 응모 접수 완료와 구분한다.
- 검토 상태, 검토자, 검토 시각, 사유를 기록한다.
- 제외 확정 전에 관리자가 사유를 확인·기록한다.
- 제외된 본인에게만 제외 사실과 사유를 안내하고 일반 낙첨과 구분한다.
- 구체적인 탐지 수치 및 다른 사용자 정보는 공개하지 않는다.
- 마감 검토는 마감 전 응모와 관련된 탐지 건을 대상으로 한다.
- 마감 후 단순 접속·재시도로 추첨 대기를 늘리지 않는다.
- 별도 이의 제기는 이번 버전에서 제외한다.
- 사용자별 요청 빈도와 비정상 요청 반복을 함께 탐지하고 출석·미션·게임 지급 단계에도 적용한다.
- 응모·출석·미션 제출·게임 결과 제출에 사용자별 요청 빈도 제한을 적용한다. 초과 시 재시도를 안내하며 부정으로 자동 확정하지 않는다.
- 세부 탐지·제한 수치는 담당자가 관리·수정한다. 확정된 적용 정책을 미결정으로 분류하지 않는다.

상세 기준은 [응모·어뷰징 규칙](../02-domain/entry.md)을 따른다.

## 9. 추첨·당첨자 관리·재추첨

- 최초 추첨·발표는 응모권 사용 여부와 관계없이 응모 마감 후 5분 검토 시간을 거쳐 자동으로 진행한다.
- 마감부터 5분 동안 어뷰징 탐지·관리자 검토와 예외 처리를 수행하고, 명단 확정 시 제외가 확정된 사용자만 제외한다. 미검토 의심만으로 제외하지 않는다.
- 경품별 당첨 인원과 데이터 정합성을 보장한다. 새로운 재추첨은 결과가 달라질 수 있으나, 이미 확정된 동일 실행의 재요청에는 저장된 결과를 반환한다.
- 재추첨은 관리자의 당첨 취소 요청에 입력한 사유를 업무 근거로 삼아 실행한다. 취소 확정과 연결 실행 등록을 함께 보장하고 등록된 실행을 즉시 시작한다.
- 사용자 요청에 의한 당첨 취소와 임의 재추첨은 제공하지 않는다.
- 관리자가 당첨자의 자격 미달·어뷰징을 확인하면 해당 당첨을 취소하고 즉시 재추첨한다. 취소 대상이 아닌 기존 당첨자와 배정된 경품은 유지한다.
- 낙첨자 부정만으로 재추첨하지 않는다.
- 재추첨 후보는 기존 유효 낙첨자이며 원래 응모 자격·가중치를 유지하고 이후 제외 확정자를 제거한다.
- 재추첨 연출·진행 과정은 관리자 화면에만 제공한다.
- 당첨자 목록, 경품 내역, 당첨 순서, 관리자 실행 이력을 관리한다.

추첨 명단·정합성·재추첨·가중치·결과 보존 규칙은 [추첨 도메인 규칙](../02-domain/drawing.md)을 따른다.

## 10. 결과 발표

- 정상 최초 결과 발표 예정 시각은 응모 마감 시각 + 5분이다. 이벤트 유형과 관계없이 별도 관리자 승인 없이 자동으로 최초 발표를 시작한다. 최초 공개 전 취소·재추첨이 발생하면 [추첨 도메인 규칙](../02-domain/drawing.md#결과-발표)에 따라 확인된 최종 명단을 공개하며, 준비·확인이 늦으면 최초 발표를 지연한다.
- 5분 검토 시간에 탐지·예외 처리를 수행하고 발표할 결과를 준비한다. 실제 선정은 1등 → 2등 → 3등 순서로 수행하며, 서버가 확정한 결과를 화면에서 3등 → 2등 → 1등 순서로 발표한다.
- 발표 전 당첨 결과는 비공개로 유지한다.
- 발표 시각과 공개 여부는 서버 기준이다. 화면의 타이머가 끝났다는 이유만으로 미공개 결과를 노출하거나 프론트엔드에서 당첨자를 선정하지 않는다.
- 최초 발표는 재시도·동시 요청에도 한 번만 반영한다. 발표 전에 취소되거나 응모자 없음·추첨 대상자 없음으로 종료된 이벤트는 당첨 발표 대신 해당 종료 상태를 표시한다.
- 발표 후 당첨 취소·재추첨이 발생하면 관리자가 재추첨 결과를 확인한 후 공개 당첨자 명단을 갱신하며, 별도 재발표는 하지 않는다.
- 재추첨 결과가 확정돼도 자동으로 공개 명단에 반영하지 않으며, 관리자 확인 전에는 새 당첨 결과를 비공개로 유지한다.
- 최초 추첨·당첨 취소·재추첨 결과와 연결 관계를 보존한다.
- 관리자는 명단의 변경 대상, 변경 전후 정보, 처리자, 시각과 사유를 조회할 수 있어야 한다. 확인자와 실제 공개 명단 갱신 시각도 변경 이력에 남긴다.
- 당첨 취소·명단 변경 이력을 이유로 내부 검토 사유나 다른 사용자의 비공개 정보를 일반 사용자에게 노출하지 않는다.
- 마감부터 최초 발표까지 '응모 마감 · 결과 발표까지 MM:SS'와 05:00부터의 카운트다운을 표시한다. 서버의 발표 예정 시각을 기준으로 남은 시간을 계산하며 새로고침·재접속으로 5분을 다시 시작하지 않는다. 내부 검토 사유는 공개하지 않는다.
- 대상 없는 종료 표시와 제외 당사자 안내는 별도로 제공한다.
- 발표 결과에는 마스킹한 이름·전화번호·이메일과 당첨 경품을 표시한다. 마스킹 세부 규칙은 담당자가 결정한다.
- 공개 화면과 응답 데이터 모두에 마스킹을 적용한다.
- 본인 화면에는 자신의 당첨 여부와 경품을 명확히 표시한다.

## 11. 백오피스

### 신규 확정 관리 기능

- 기본 출석 보상 수량, 연속 출석 단계 일수와 단계별 보상 수량 관리. 단계는 1~28일 범위에서 중복 없이 오름차순으로 설정한다.
- 서비스 공통 미션(퀴즈·설문)과 문항 생성·관리.
- 미션별 별도 운영 기간 설정. 완료 보상은 등급 응모권 1장으로 고정하며 반복 주기는 제공하지 않는다.
- 게임 관리.
- 미션 보상의 등급별 지급 현황 확인. 확률과 가중치의 관리자 변경 기능은 이번 결정으로 추가하지 않는다.
- 게임 보상 획득 조건 관리. 사용자별·게임별 하루 1회 1장 제한은 유지한다.
- 이벤트 유형, 이벤트별 최소 허용 멤버십 등급, 경품 구성, 모집 시작·마감 시각, 가중치 적용 여부 관리.
- 이벤트 중단·재개·취소 및 응모권 반환 처리 이력 확인.
- 배너 관리.

### 기존 운영 기능 유지

- 이벤트·검토·추첨 실행·당첨자·결과 발표 통합 관리.
- 추첨 실행 이력 및 정합성 검증 결과 확인.
- 재추첨 결과 확인 후 공개 당첨 명단 갱신 및 변경 이력 조회.
- 모의 알림 이력 확인.
- 사용자 목록·정보 조회만 제공하며 사용자 정보 수정은 허용하지 않는다.

### 정책 변경 적용 시점

- 기본 출석·허용된 게임 보상 정책 변경은 다음 일일 기준일(00:00 KST)부터 적용한다.
- 연속 출석 단계·보상 변경은 다음 KST 기준월부터 적용한다.
- 미션 조건·문항·보상 변경은 신규 등록 미션에 적용한다. 운영 중인 미션과 기존 달성·지급 이력을 소급 변경하지 않는다.
- 게임의 사용자별·게임별 하루 1회 1장 제한 등 기존 확정 규칙은 유지한다.

### 응모권 지급 현황·검색

- 지급 응모권 수를 조회한다.
- 응모권 이력 합계와 잔액의 일치 상태를 표시한다.
- 사용자·사용자 ID를 검색한다.
- 미션·기간으로 필터링한다.
- 페이지 이동 및 페이지당 표시 개수를 설정한다.

### 부정 획득 응모권 회수

- 관리자는 부정 획득이 확인된 응모권을 회수할 수 있다.
- 부정 지급 의심만으로 회수하지 않는다. 관리자가 이력과 근거를 검토하고 부정 획득을 확인한 후 회수를 결정한다.
- 한 검토 건에서 동일 사용자의 여러 지급 건을 회수 대상으로 지정할 수 있으며, 지급 건별 회수 대상 수량을 기록한다.
- 회수 결정과 실제 회수 결과를 구분한다. 현재 회수할 수 없는 지급분도 원본 지급 건과 회수 대상 수량을 보존하며, 실제 회수는 근거가 된 검토 결정과 연결한다.
- 이벤트 제외 사실만으로 정상 지급된 응모권을 부정 획득분으로 회수하지 않는다. 다른 정상 지급분을 대신 차감하지 않는다.
- 같은 지급 건이 여러 검토에 포함돼도 회수 대상 수량을 단순 합산하지 않고 기존 결정·회수·만료 이력을 확인한다.
- 확정 판단을 변경할 때 기존 판단과 실제 회수 이력을 보존한다.
- 응모권 잔액을 직접 덮어쓰지 않고, 원본 지급 이력에 연결된 회수 이력을 추가한다.
- 회수 시 대상 사용자, 원본 지급 건, 회수 수량, 사유, 처리자, 처리 시각을 기록한다.
- 같은 지급 건에서 이미 회수한 수량을 다시 회수하지 않는다.
- 이미 만료되거나 회수된 수량은 중복 차감하지 않으며, 잔액을 음수로 만들지 않는다.
- 부정 획득분이 이미 응모에 차감됐다면 해당 응모를 검토한다. 제외 처리로 반환되는 부정 획득분은 반환과 회수를 같은 트랜잭션으로 처리해 중간 재사용을 막는다.
- 당첨 후 부정이 확인되면 당첨 취소·재추첨 정책을 적용한다.
- 사용자에게 회수 수량과 사유를 알린다.
- 임의 지급·잔액 수정은 제공하지 않고, 부정 획득분 회수만 허용한다.

## 12. 알림

- 사용자별 사이트 내 알림함을 제공한다.
- 알림에는 제목, 내용, 생성 시각, 읽음 여부, 관련 이벤트 링크를 포함한다.
- 알림 목록 조회, 개별 읽음, 전체 읽음 처리를 제공한다.
- 사용자가 해당 알림을 클릭하면 개별 읽음 처리한다. 목록 조회만으로는 읽음 처리하지 않는다.
- 읽음·미읽음 여부만 관리하며 읽음 시각은 저장하지 않는다.
- 전체 읽음은 해당 사용자의 미읽음 알림 전체를 읽음 처리한다. 이미 읽은 알림과 다른 사용자의 알림 상태는 변경하지 않는다.
- 개별·전체 읽음 처리는 알림 소유자 본인만 할 수 있으며, 관리자는 다른 사용자의 알림을 대신 읽음 처리할 수 없다.
- 모의 발송 결과와 읽음 상태는 별개이며, 발송 성공만으로 읽음 처리하지 않는다.
- 실제 문자·이메일·외부 푸시는 이번 버전에서 제외한다.

알림 생성·재시도·중복 방지 규칙은 [알림 도메인 규칙](../02-domain/notification.md)을 따른다.

## 13. 배너

- 노출 순서는 관리자가 설정한다.
- 별도 노출 기간은 두지 않는다.
- 관리자는 배너를 등록·수정·삭제한다.
- 배너는 이미지 형식이며 선택하면 연결된 이벤트 페이지로 이동한다.
- 연결된 이벤트 삭제 시 배너 처리는 [이벤트 도메인 규칙](../02-domain/event.md)을 따른다.
- 배너는 자동 슬라이드와 좌우 화살표 이동을 지원한다.
- 배너는 최대 5개까지 등록한다.
- 이미지 형식·용량 제한은 담당자가 추후 확정한다. 아직 전달되지 않은 비기능 요구사항을 확정 기준으로 참조하지 않는다.
