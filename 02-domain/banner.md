# 배너 도메인 규칙

- 상태: 확정 — 2026-10-15 사용자 모델·노출 방향 및 상세 계약 선택 반영
- 요구사항: [배너](../00-requirements/functional-requirements.md#13-배너)
- 처리 계약: [배너 API](../05-api/banner.md)

## 연결과 노출

- 배너는 이벤트 ID로 연결한다. 신규 등록·수정은 서버에서 연결 이벤트 존재를 검증한다.
- 사용자 목록은 연결 이벤트가 삭제·취소됐으면 해당 배너를 제외한다. 배너 행은 유지하고 관리자 목록에는 포함한다.
- 배너 삭제는 관리자가 별도로 수행한다. 이벤트 삭제에 배너 자동 삭제나 연결 배너를 이유로 한 이벤트 삭제 제한을 추가하지 않는다([ADR-021](../03-decisions/021-manual-banner-deletion.md)).
- 그 밖의 이벤트 상태에 대한 새 노출 기간·자동 삭제 규칙은 추가하지 않는다.

## 순서와 개수

- 관리 목록은 최대5개, 순서는1~N(N≤5)이다.
- 원하는 자리에 새 배너를 등록하면 기존 배너를 뒤로 밀고, 삭제하면 빈자리를 당긴다.
- 기존 배너 이동은 이동 구간의 순서를 조정한다. 사용자 목록은 숨김 대상을 제외하되 관리 순서의 상대 순서를 유지한다.
- 숨긴 배너도 전체5개 제한에 포함한다.

## 이미지와 처리자

- DB에는 이미지 키를 저장하고 사용자 응답의 이미지 URL은 공개 기준 주소에서 만든다. 저장소 접근 주소와 공개 주소를 분리하고 저장소 접근 주소를 사용자 응답에 노출하지 않는다.
- 이미지 실제 업로드·키 형식·허용 형식·용량과 실제 저장소 주소는 담당자 연동 확인 대상이다. 임의 제공자·5MB 정책·작동하지 않는 주소로 대신하지 않는다.
- 처리자는 공통 감사 기록으로 추적하며 별도 createdBy 응답 필드를 추가하지 않는다.
- 2026-10-16 사용자 선택: 기존 URL·행은 보존하고 이벤트 ID가 미연결인 이전 배너는 사용자에게 숨기되 관리자에게 남긴다. 신규 등록·수정의 이벤트 ID는 필수다. 응답의 null 예외와 이전 순서는 [배너 API의 이전 데이터 예외](../05-api/banner.md#이전-url-배너-보존--2026-10-16-사용자-선택)를 따른다. 기존 행이 없다고 가정하거나 URL에서 ID를 추측해 일괄 변경·삭제하지 않는다. DB 이전 절차는 백엔드에서 관리한다.
