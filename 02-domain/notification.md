# 알림 도메인 규칙

## 수신 방식

- 사용자별 사이트 내 알림함을 제공한다.
- 알림에는 제목, 내용, 생성 시각, 읽음 여부, 관련 이벤트 링크를 포함한다.
- 알림 목록 조회, 개별 읽음, 전체 읽음 처리를 제공한다.
- 사용자가 해당 알림을 클릭하면 개별 읽음 처리한다. 목록 조회만으로는 읽음 처리하지 않는다.
- 읽음·미읽음 여부만 관리하며 읽음 시각은 저장하지 않는다.
- 전체 읽음은 해당 사용자의 미읽음 알림 전체를 읽음 처리한다. 이미 읽은 알림과 다른 사용자의 알림 상태는 변경하지 않는다.
- 개별·전체 읽음 처리는 알림 소유자 본인만 할 수 있으며, 관리자는 다른 사용자의 알림을 대신 읽음 처리할 수 없다.
- 모의 발송 결과와 읽음 상태는 별개이며, 발송 성공만으로 읽음 처리하지 않는다.
- 실제 문자·이메일·외부 푸시는 이번 버전에서 제외한다.

## 이벤트 시작 알림

- 별도 신청 없이 해당 이벤트의 응모 자격을 충족하는 사용자 전원에게 전송한다.
- 응모와 동일하게 이벤트의 최소 멤버십 등급 이상 조건을 적용한다. 등급 순서는 우수 < VIP < VVIP다.
- 시작 시각 10분 전에 1회 생성한다. 시작 시각에는 별도로 생성하지 않는다.
- 알림 생성 시점의 사용자·멤버십 정보로 대상을 판정한다. 실제 응모 시에는 자격을 다시 확인한다.
- 내용은 이벤트 시작 사전 안내와 이벤트 링크다.

## 일정 변경·취소 알림

- [이벤트 규칙](event.md#수정-및-삭제-제한)에서 허용한 시작 전 일정 변경에만 알림 예약 갱신과 변경 안내를 적용한다. 시작 시각을 앞당기는 요청은 허용하지 않으며 알림·예약에도 반영하지 않는다.
- 허용된 일정 변경 시 아직 생성하지 않은 시작 알림 예약을 새 시작 시각 10분 전으로 갱신한다. 취소 시 미생성 예약을 제거한다.
- 허용된 일정 변경이나 취소 시, 시작 알림을 이미 받은 사용자에게 변경·취소 안내를 별도로 제공한다.
- 별도 안내 대상인 변경·취소 건은 기존 알림을 수정해 대체하지 않는다. 변경된 시작 시각 또는 취소 사실과 이벤트 링크를 새 알림으로 안내한다.
- 변경 안내는 시작 알림 재발송과 구분하며, 같은 변경 건의 재처리로 중복 생성하지 않는다.

## 결과 발표 알림

- 대상은 해당 이벤트 응모자 전원이다.
- 응모 마감 5분 후 최초 결과가 자동 공개될 때 결과 확인 안내와 이벤트 링크를 담은 알림을 생성한다. 당첨·낙첨 여부와 경품은 결과 화면에서 확인한다.
- 서버의 최초 자동 발표 전에는 당첨 결과를 공개하지 않는다. 알림은 타이머 종료만으로 생성하지 않고 실제 공개에 연결한다.
- 대상, 내용, 발생 사유, 생성·모의 발송 시각, 처리 결과를 기록한다.

## 공통 처리 기준

- 알림은 비동기로 생성한다.
- 결과 발표는 전체 알림 생성 완료를 기다리지 않는다.
- 동일 발생 건을 재처리해도 알림이 중복 생성되지 않도록 한다.
- 최초 발표 알림은 유지한다. 발표 후 명단 갱신은 별도 재발표로 처리하지 않는다.
- 관리자 확인 후 공개 명단을 갱신하면 당첨 취소자와 새 당첨자에게만 결과 변경 안내와 확인 링크를 제공한다. 다른 응모자에게는 보내지 않는다.
- 변경 알림에 다른 사용자의 개인정보나 내부 어뷰징 검토 내용, 재추첨 진행 과정을 포함하지 않는다.
- 실제 발송은 모킹 처리한다.

## 실패 재시도 및 관리자 복구

- 이벤트 시작 알림의 정상 동작은 시작 10분 전 자동 1회 생성이다. 정상 완료된 알림을 다시 생성·발송하는 기능은 제공하지 않는다.
- 알림 생성과 모의 발송의 실패 처리를 구분한다. 각 실패 처리에는 최초 시도 외에 최대 3회의 자동 재시도를 적용한다. 최초 시도를 포함하면 최대 4회다.
- 자동 재시도는 일시적인 DB 접근·연결 장애와 모의 발송의 일시적 실패에 적용한다. 입력·데이터 형식·제약 오류처럼 반복 실행으로 해결되지 않는 오류는 3회를 기다리지 않고 즉시 최종 실패로 기록한다.
- 자동 재시도 중 성공하면 해당 처리를 종료하며 남은 재시도를 수행하지 않는다.
- 최대 3회의 자동 재시도 후에도 완료되지 않으면 최종 실패로 기록하고, 시스템의 자동 재시도를 중단한다. 관리자는 최종 실패 건을 확인하고 처리 복구를 요청할 수 있다.
- 생성 실패를 재처리할 때는 최초 수신 대상과 내용을 유지하고 아직 생성하지 못한 알림을 처리한다. 이미 생성된 사용자 알림을 복제하거나 덮어쓰지 않는다.
- 모의 발송 실패를 재처리할 때는 이미 생성된 동일 알림의 발송 처리만 재시도한다. 새 사용자 알림을 만들거나 읽음 상태를 변경하지 않는다.
- 이벤트가 이미 시작했거나 취소·삭제된 경우, 시작 사전 안내의 관리자 생성 복구는 허용하지 않는다. 기존 자동 작업의 생성 시점 및 이미 생성된 알림의 모의 발송 처리를 이 제한으로 변경하지 않는다.
- 관리자 복구를 접수하면 최초 1회와 최대 3회의 자동 재시도로 구성된 새 복구 구간을 제공하며, 일시적 오류만 자동 재시도하는 기준을 유지한다.
- 관리자 복구는 최종 실패 건의 처리 복구다. 자동 재시도 대기·처리 중·정상 완료된 건과 일정 변경·취소로 생성이 중지된 시작 작업은 복구 대상으로 처리하지 않는다.

## 2026-10-12 실패 처리 정책 명확화

- 변경 전: 생성 실패 시 재시도하고 최종 실패는 관리자가 재처리한다는 원칙만 기재되어 있었다. 자동 재시도 횟수와 정상 알림의 재발송 구분은 명시하지 않았다.
- 변경 후: 최초 처리 1회와 실패 시 최대 3회의 자동 재시도, 이후 최종 실패의 관리자 복구를 명시했다. 생성 복구와 모의 발송 복구를 구분하고 정상 알림의 중복 생성·발송은 제공하지 않는다.
