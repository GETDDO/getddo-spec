# 추첨 도메인 규칙

## 추첨 대상 확정 및 실행

- 마감 전 접수 완료된 유효 응모를 누락·중복 없이 반영한다.
- 정상 접수된 유효 응모를 실제 수량·차감 근거와 대조하여 후보로 확정한다. 어뷰징 검토에 따른 응모자 제외를 수행하지 않으며, 차단 기록으로 같은 사용자의 다른 정상 응모를 제거하지 않는다.
- 유효 응모 처리와 명단·가중치의 일치를 확인한 뒤 실행별 명단을 확정한다.
- 최초 추첨은 응모권 사용 여부와 관계없이 응모 마감 5분 후 자동으로 진행한다. 최초 발표는 관리자 명단 검토·확인 후 명시적 수동 공개로 처리한다.
- 추첨은 어뷰징 검토 완료나 제외 저장소 연결을 선행 조건으로 요구하지 않는다. 마감 +5분은 자동 추첨 기준으로 유지하며 고정된 발표 시각으로 사용하지 않는다.

## 근거 보존 및 정합성

- 최초 추첨과 각 재추첨에 사용한 후보 명단, 응모권 수, 가중치, 경품별 당첨 인원과 조건을 실행별 스냅샷으로 보관한다.
- 확정된 후보·조건 스냅샷과 결과를 기준으로 경품별 당첨 인원, 후보 유효성, 중복 당첨 여부 및 실행 이력의 정합성을 확인한다.
- 정합성 검증 과정에서 원본 스냅샷과 확정 결과를 변경하지 않는다.
- 사용자에게 추첨 방식과 발표된 결과를 안내한다.
- 구체적인 알고리즘은 구현 단계에서 결정한다.

## 재추첨

- 재추첨은 관리자가 수동으로 실행한다.
- 새로운 재추첨은 별도 실행으로 기록하며, 선정 결과가 이전 실행과 달라질 수 있다.
- 관리자는 취소 요청에 사유를 입력하며 연결된 취소 사유를 재추첨의 업무 근거로 보존·조회한다. 취소 처리자와 이후 실행 시작·재개 행위의 처리자는 구분한다.
- 재추첨은 이력에 남기며, 최초 추첨과의 연결 관계를 보존한다.
- 사용자 요청에 의한 당첨 취소는 제공하지 않는다. 당첨 취소에 연결되지 않은 임의 재추첨이나 확정된 동일 실행의 재선정은 제공하지 않는다.
- 관리자는 취소 사유를 기록하여 개별 당첨을 취소하고 빈 자리만 재추첨할 수 있다. 어뷰징·자격 미달 확인을 필수 조건으로 요구하지 않는다. 당첨 취소·재추첨을 이유로 응모권을 반환하거나 회수하지 않는다. 취소 대상이 아닌 기존 당첨자와 배정된 경품은 유지한다. 자동 탐지·차단 기록만으로 당첨을 자동 취소하거나 정상 응모를 추첨에서 제외하지 않는다.
- 낙첨자의 부정만으로 자동 재추첨하거나 다른 정상 응모를 제외하지 않는다. 기존 당첨 결과를 유지하며 지급 후 부정의 점수 처리·근거 연계는 별도 후속 확인한다.
- 최초 발표 후 30일 등 별도 일수 제한은 채택하지 않았다. 관리자 사유에 따른 개별 취소에 연결된 재추첨으로 처리한다.
- 당첨 취소에 따른 재추첨은 취소로 빈 경품별 자리만 대상으로 하며, 유지되는 당첨자를 다시 선정하지 않는다.
- 재추첨 후보는 원래 이벤트의 유효한 낙첨자다. 기존 당첨자와 당첨 취소자는 제거한다. 어뷰징 차단 이력에 따른 추가 응모자 제외는 수행하지 않는다. 신규 응모 모집이나 예비 순번 승계는 제공하지 않는다.
- 멤버십 등 원래 응모 자격을 유지한다. 관리자 사유에 따른 개별 당첨 취소·빈 자리 재추첨은 확정 범위다. 선택적인 어뷰징 근거 연결은 후속 확인하며 이벤트 응모자 제외 결정으로 확장하지 않는다.
- 가중치 적용 이벤트는 남은 후보의 최초 추첨 당시 가중치를 유지한다. 미적용 이벤트는 동일 가중치를 유지한다.
- 재추첨 상태는 관리자 실행 시작부터 결과 확인과 명시적 공개 명단 반영까지 유지한다. 발표된 이벤트는 수동 반영 후 결과 발표 완료로 돌아간다. 최초 공개 전 결과는 관리자 공개 요청 전까지 비공개로 유지한다.
- 재추첨 진행 과정과 연출은 일반 사용자에게 공개하지 않는다. 연출은 관리자 화면에만 제공한다. 사용자에게는 관리자 확인 후 갱신된 명단과 본인 결과를 제공한다.

## 가중치 및 중복 당첨

- 응모권 사용 이벤트는 가중치 적용·미적용 방식으로 구분한다.
- 일반 가중치 적용 이벤트는 사용자당 해당 이벤트에서 추가 응모를 포함해 응모권을 누적 최대 5장까지 사용할 수 있다. 1회 요청당 제한이 아니라 이벤트별 사용자 누적 사용 상한이다. 월말 소진용 이벤트의 상한 없음 예외는 [응모권 규칙](ticket.md)을 따른다.
- 가중치 적용 이벤트의 등급 응모권은 실제 차감한 등급별 장수에 장당 가중치를 곱해 합산한다. 브론즈 1, 실버 3, 골드 5를 적용하며, 등급 응모권의 가중치 합계는 `브론즈 차감 장수 × 1 + 실버 차감 장수 × 3 + 골드 차감 장수 × 5`다. 추가 응모도 합산하고 요청 수량이나 거절된 응모는 반영하지 않는다.
- 응모권 사용 수량과 별개로 가중치 값에 추가 상한을 두지 않는다. 등급 응모권 5장을 사용할 때 골드 5장이면 가중치는 25가 된다. 월말 소진용 이벤트는 유효 보유량 내에서 사용한 등급별 가중치를 별도 상한 없이 합산한다. 등급별 장당 가중치 외의 추가 배율은 적용하지 않는다.
- 예: 골드 1장·실버 1장·브론즈 1장을 차감한 경우 실제 사용량은 3장, 추첨 가중치는 9다. 최초 후보 스냅샷에는 실제 장수와 확정 가중치를 구분해 보존하며 재추첨에서는 최초 가중치를 유지한다.
- 가중치 미적용 이벤트는 응모권 1장을 차감해 응모하며 응모자별 추첨 가중치는 1이다.
- 응모권 미사용 이벤트는 이벤트 단위 응모를 기준으로 추첨하며 응모자별 추첨 기회와 가중치는 1이다.
- 이벤트 하나에서 동일 사용자의 중복 당첨을 허용하지 않는다. 같은 경품과 다른 경품 모두 동일하게 적용한다.
- 실제 등수별 당첨자 선정·경품 배정은 1등 → 2등 → 3등 순서로 진행한다. 이미 당첨된 사용자는 다음 등수 추첨에서 제외한다.
- 유효 후보가 전체 당첨 인원보다 적으면 같은 순서로 상위 등수부터 배정하고, 후보가 소진된 뒤 남은 자리는 미선정으로 처리한다.

## 대상 부족 및 결과 관리

- 각 실행의 유효 후보 안에서만 당첨자를 선정한다.
- 경품별 설정 인원을 준수하며, 유지되는 기존 당첨자와 새 당첨자의 합계가 해당 경품의 설정 인원을 초과하지 않는다.
- 최초 추첨에서 유효 후보가 전체 당첨 인원보다 적으면 전원 당첨시키고 남은 자리는 미선정으로 처리한다.
- 재추첨에서 유효 후보가 보충할 자리보다 적으면 가능한 인원만 선정하고 남은 자리는 미선정으로 처리한다.
- 최초 추첨에서 응모자가 없으면 추첨 없이 '응모자 없음'으로 종료·표시한다.
- 어뷰징으로 전원 제외되는 종료 흐름은 신규 실행에서 사용하지 않는다. 과거 실행의 상태·스냅샷·결과 이력은 소급 변경하지 않으며 조회 호환성은 구현 시 검토한다.
- 당첨자 목록, 경품 내역, 당첨 순서, 관리자 실행 이력을 관리한다.
- 최초 추첨과 각 재추첨 실행은 동시 요청·처리 중단 후 재시도에도 각각 하나의 결과만 확정한다.
- 이미 확정된 동일 실행을 다시 요청하면 저장된 확정 결과를 반환하며, 다시 선정하거나 결과·당첨 순서를 변경하지 않는다.
- 새로운 재추첨과 동일 실행의 재시도를 구분하고, 동일한 당첨 취소 건의 재시도·동시 요청이 별도 재추첨으로 중복 반영되지 않도록 한다.
- 재추첨으로 최초 추첨이나 이전 재추첨 결과를 덮어쓰지 않고 이력과 출처를 보존한다.

## 결과 발표

- 자동 추첨 → 관리자 명단 검토 → 필요 시 개별 당첨 취소·빈 자리 재추첨 → 최종 명단 확인 → 명시적 수동 공개 → 프론트엔드 발표 순서로 처리한다. 정상 최초 결과도 관리자 확인과 공개 요청을 요구한다.
- 마감 +5분은 자동 추첨 실행 기준이다. 실제 선정은 1등 → 2등 → 3등이며, 사용자 화면은 관리자가 공개한 결과를 3등 → 2등 → 1등 순서로 연출한다.
- 발표 전 당첨 결과는 비공개로 유지한다.
- 발표 시각과 공개 여부는 서버 기준이다. 화면의 타이머가 끝났다는 이유만으로 미공개 결과를 노출하거나 프론트엔드에서 당첨자를 선정하지 않는다.
- 최초 발표는 재시도·동시 요청에도 한 번만 반영한다. 발표 전에 취소되거나 응모자 없음으로 종료된 이벤트는 당첨 발표 대신 해당 종료 상태를 표시한다.
- 발표 후 당첨 취소·재추첨이 발생하면 관리자가 재추첨 결과를 확인한 후 공개 당첨자 명단을 갱신하며, 별도 재발표는 하지 않는다.
- 최초 추첨·재추첨 결과 확정이나 관리자 확인 저장만으로 공개하지 않는다. 확인과 실제 공개는 별도 동작이며 스케줄러의 자동 공개·공개 재호출은 수행하지 않는다.
- 최초 공개 전 당첨 취소·재추첨이 발생하면 유지 결과와 관리자 확인된 새 결과를 합쳐 최종 명단을 구성한다. 모든 필요한 실행·확인이 준비된 뒤 관리자 공개 요청에서 전체 명단을 원자적으로 공개한다. 미확인 결과나 일부 명단을 먼저 공개하지 않는다. 검토 중 명단이 변경되면 변경된 결과를 다시 확인하고 이전 확인으로 새 결과를 공개하지 않는다.
- 최초 추첨·당첨 취소·재추첨 결과와 연결 관계를 보존한다.
- 관리자는 명단의 변경 대상, 변경 전후 정보, 처리자, 시각과 사유를 조회할 수 있어야 한다. 확인자와 실제 공개 명단 갱신 시각도 변경 이력에 남긴다.
- 당첨 취소·명단 변경 이력을 이유로 내부 검토 사유나 다른 사용자의 비공개 정보를 일반 사용자에게 노출하지 않는다.
- 추첨 결과는 백엔드에서 모두 확정하고, 프론트엔드는 확정된 결과를 3등 → 2등 → 1등 순서로 표시한다. 이 순서는 화면 표시 순서이며 실제 당첨자 선정 순서를 의미하지 않는다.
- 마감부터 실제 공개까지 '응모 마감 · 결과 발표 대기'를 표시한다. 발표까지 5분 카운트다운·고정 발표 예정 시각·새 예정 시각은 제공하지 않는다. 내부 검토·취소·재추첨 과정과 사유는 공개하지 않는다.
- 응모자가 없는 경우에는 정상 종료 상태를 표시한다. 신규 추첨 제외 사유 안내는 제공하지 않는다.
- 발표 결과에는 마스킹한 이름과 전화번호 끝 4자리를 당첨 경품과 함께 표시한다. 이메일은 표시하거나 공개 응답에 포함하지 않는다. 닉네임 표시 정책을 대체한다.
- 외자 이름은 성만 드러내고 나머지를 가린다(예: 김수 → 김*). 그 외 이름은 처음과 마지막 글자만 드러내고 사이를 가린다(예: 김민수 → 김*수, 남궁민수 → 남**수). 미등록 값의 별도 표시·대체 문구는 이번 작업 범위에서 다루지 않는다.
- 공개 화면과 응답 데이터 모두에 마스킹을 적용한다.
- 본인 화면에는 자신의 당첨 여부와 경품을 명확히 표시한다.

## 보관과 개인정보

- 최초 추첨·재추첨 후보·조건 스냅샷과 결과 이력의 운영상 보관 기간은 이벤트의 마지막 결과 공개 또는 취소 후 5년이다. 재추첨 결과를 공개하면 마지막 공개 시점을 갱신한다. 보관 정책은 추후 수정할 수 있다.
- 이 5년은 서비스 운영 정책이며 전체 추첨 자료에 일괄 적용되는 법정 보존 의무라고 설명하지 않는다.
- 탈퇴 기능은 제공하지 않는다. 탈퇴 기능 유무와 무관하게 개인정보가 불필요해지면 보관 근거에 따라 파기하고, 법령상 보존 의무가 있는 정보는 분리 보관한다. 개인정보 전체를 무조건 5년 보존하는 근거로 운영 정책을 사용하지 않는다.
- 개인정보의 파기·별도 보관과 추첨 근거 보존을 함께 만족할 구체적인 저장 방식은 확정하지 않았다. 질문에서 제안한 익명화·집계 방안 중 하나를 사용자 선택 없이 확정하지 않는다.
- 법령 참고: [개인정보 보호법 제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?ancYnChk=&chrClsCd=010202&lsJoLnkSeq=1020398651), [전자상거래법 시행령 제6조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0006&lsiSeq=269055&urlMode=lsScJoRltInfoR). 거래기록 해당 여부와 적용 근거를 확인해야 하며 추첨 기록 전체에 전자상거래의 5년을 자동 적용하지 않는다.

등급 응모권의 지급·가중치 결정은 [ADR-014](../03-decisions/014-random-ticket-grades.md)을 따른다. 종전 장수 환산 결정은 [ADR-013](../03-decisions/013-linear-drawing-weight.md)에 보존한다. 마스킹은 위 결과 발표 규칙을 따르며, 나머지 담당자 후속 항목은 [미결정·후속 사항](../00-requirements/pending-decisions.md#추첨과-결과-발표)을 따른다.

## 2026-10-05 변경 범위

- 변경 전: 최초 공개 전 취소·재추첨의 확인과 최초 명단 구성은 미확정이었다.
- 변경 후: 유지 당첨자와 확인된 재추첨 결과를 합쳐 최초 공개하고, 준비·확인이 늦으면 발표를 지연한다. 정상 마감 + 5분 자동 최초 발표는 유지한다.
- 실행 사유·처리자 조회는 연결 취소의 근거와 실행 시작·재개 행위를 구분한다. 상세 요청·응답은 [API 초안](../05-api/drawing.md), 내부 저장 방식은 백엔드 문서를 따른다.

## 2026-10-11 변경 범위

- 변경 전: 제외 확정자를 걸러 후보를 만들고 전원 제외 종료를 제공했다.
- 변경 후: 정상 접수된 유효 응모를 정합성 검증 후 후보로 확정하며 추첨 제외 의존성을 제거한다. 수량·가중치·중복 당첨·결과 검증과 응모자 없음 종료는 유지한다.
- 기존 사후 당첨 취소·재추첨과 마감 후 5분 일정은 후속 결정 전까지 유지한다.
- 결정 기록: [ADR-018](../03-decisions/018-pre-issuance-abuse-blocking-and-no-draw-exclusion.md).

## 2026-10-12 관리자 개별 취소·재추첨 범위 확정

- 변경 전: 당첨자의 자격 미달·어뷰징 확인을 취소 근거로 제한하고 사후 취소·재추첨 유지 여부를 후속 확인으로 남겼다.
- 변경 후: 관리자는 취소 사유를 기록하여 개별 당첨을 취소하고 빈 자리만 재추첨할 수 있다. 어뷰징·자격 미달 확인을 필수 조건으로 요구하지 않는다. 당첨 취소·재추첨을 이유로 응모권을 반환하거나 회수하지 않는다. 다른 당첨자·경품과 최초 가중치를 유지한다.
- 전체 당첨자를 취소하고 처음부터 다시 추첨하는 기능은 추후 추가 예정이며 이번 구현에서 제외한다.
- 당첨 취소와 재추첨 등록의 원자성, 실패한 동일 실행 재개, 확정 결과 불변과 공개 전 관리자 확인은 기존 규칙을 유지한다.
- 결정 기록: [ADR-019](../03-decisions/019-admin-award-cancellation-and-partial-redraw.md).

## 2026-10-13 공개·조회 연동 원칙

- 변경 전: 복수 재추첨 공개의 대표 메타데이터와 실패·감사 조회 제공 방향을 후속 확인으로 남겼다.
- 변경 후: 공개 버전의 단일 사유·확인자·확인 시각은 계기 실행을 의미한다. 실제 반영된 실행별 취소 사유와 관리자 확인 근거를 목록으로 조회할 수 있게 보존한다. 원래 실행·취소·확인 이력을 합쳐 덮어쓰지 않는다.
- 관리자 실행 상세의 실패·예약·운영자 대기·취소 근거 요약과 전체 실패 이력 페이징 조회는 유지한다. 2026-10-15 사용자 결정으로 공통 감사 로그 조회는 제외하고 내부 감사 기록은 유지한다([감사 기록 명세](../05-api/audit.md)).
- 공개 저장과 함께 전달 근거를 보존하고 커밋 후 기존 알림 기능을 호출한다. 실패한 전달은 재전달하며 공개 식별자로 중복을 방지한다. 전달·발송 실패로 이미 확정된 공개를 롤백하거나 재선정하지 않는다.
- 이벤트 상태 변경 연결은 기존 담당 코드가 있으면 재사용하고, 없으면 GD-169에서 새 기능을 만들지 않고 미연결로 기록한다. 기능 구현 범위와 상태의 도메인 의미를 구분한다.
- 종료 응답·멱등 키·오류 코드·API 기준은 [추첨 API](../05-api/drawing.md#2026-10-13-gd-169-연동-계약-확정)를 따른다. 기록은 구현 완료를 의미하지 않는다.

## 2026-10-14 사용자 결과 조회 범위 확인

- 변경 전: 이름·전화번호·이메일의 구체적 마스킹과 발표 후 취소·재추첨 중 사용자 표시를 후속 확인으로 남겼다.
- 변경 후: 결과 발표 절의 이름·전화번호 규칙을 사용하고 이메일은 제외한다. 사용자 조회 API의 E08·E09 초안을 채택한다.
- 이번 운영에서는 발표 후 당첨 취소·재추첨을 사용하지 않는다는 사용자 전제로, 그 사이 취소자 임시 표시·본인 중간 상태는 GD-140 구현 범위에서 제외한다.
- 기존 관리자 취소·재추첨 정책과 API·코드는 유지한다. 발표 후 요청 차단이나 취소 기능 삭제를 승인한 것이 아니며, 기존 API로 해당 상황을 만들 수 있다는 점은 유지된다. 운영에서 사용하려면 사용자 중간 표시 계약을 먼저 보완한다.
- 최초 공개 전 취소·재추첨의 최종 명단 구성과 공개 전 비노출은 유지한다. 공개 시점은 아래 2026-10-14 수동 최초 공개 결정에 따라 관리자 요청으로 정한다.

## 2026-10-14 자동 추첨·관리자 수동 최초 공개

- 변경 전: 마감 +5분 정상 최초 자동 발표와 공개 준비 후 자동 재호출을 사용했다.
- 변경 후: 자동 추첨은 유지하되 최초 명단도 관리자 검토·확인과 별도 수동 공개를 요구한다. 발표 전 개별 당첨 취소·빈 자리 재추첨을 사용하며 응모자 후보 제외는 추가하지 않는다.
- 기존 관리자 취소·재추첨 API와 과거 공개 이력을 유지한다. 발표 후 기능의 삭제·요청 차단은 이번 결정에 포함하지 않는다.
- 확정된 결과·관리자 확인·실제 공개를 구분하며 사용자 조회·알림은 실제 공개에 연결한다.
- 결정 기록: [ADR-022](../03-decisions/022-manual-initial-publication.md). 2026-10-05 및 ADR-009의 자동 최초 발표·카운트다운 부분은 이 결정으로 대체하며 과거 기록은 보존한다.
