# 추첨 도메인 규칙

## 추첨 대상 확정 및 실행

- 마감 전 접수 완료된 유효 응모를 누락·중복 없이 반영한다.
- 추첨 명단 확정 시점에 제외가 확정된 사용자만 제외한다. 미검토 의심 사용자는 포함하며, 미검토 건 때문에 자동 추첨을 보류하지 않는다.
- 유효 응모 처리와 명단·가중치의 일치를 확인한 뒤 실행별 명단을 확정한다.
- 최초 추첨·발표는 응모권 사용 여부와 관계없이 응모 마감 후 5분 검토 시간을 거쳐 자동으로 진행한다.
- 마감부터 5분 동안 어뷰징 탐지·관리자 검토와 예외 처리를 수행하고, 명단 확정 시 제외가 확정된 사용자만 제외한다. 미검토 의심만으로 제외하지 않는다.

## 근거 보존 및 정합성

- 최초 추첨과 각 재추첨에 사용한 후보 명단, 응모권 수, 가중치, 경품별 당첨 인원과 조건을 실행별 스냅샷으로 보관한다.
- 확정된 후보·조건 스냅샷과 결과를 기준으로 경품별 당첨 인원, 후보 유효성, 중복 당첨 여부 및 실행 이력의 정합성을 확인한다.
- 정합성 검증 과정에서 원본 스냅샷과 확정 결과를 변경하지 않는다.
- 사용자에게 추첨 방식과 발표된 결과를 안내한다.
- 구체적인 알고리즘은 구현 단계에서 결정한다.

## 재추첨

- 재추첨은 관리자가 수동으로 실행한다.
- 새로운 재추첨은 별도 실행으로 기록하며, 선정 결과가 이전 실행과 달라질 수 있다.
- 관리자는 취소 요청에 사유를 입력하며 연결된 취소 사유를 재추첨의 업무 근거로 보존·조회한다. 취소 처리자와 이후 실행 시작·재개 행위의 처리자는 구분한다.
- 재추첨은 이력에 남기며, 최초 추첨과의 연결 관계를 보존한다.
- 사용자 요청에 의한 당첨 취소와 임의 재추첨은 제공하지 않는다.
- 관리자가 당첨자의 자격 미달·어뷰징을 확인하면 해당 당첨을 취소하고 즉시 재추첨한다. 탐지만으로 당첨 취소·재추첨하지 않는다. 취소 대상이 아닌 기존 당첨자와 배정된 경품은 유지한다.
- 낙첨자의 부정만으로 재추첨하지 않는다. 기존 당첨 결과를 유지하고 부정 응모·보상은 별도로 처리한다.
- 최초 발표 후 30일 등 별도 일수 제한은 채택하지 않았다. 관리자 부정 확인에 따른 즉시 재추첨으로 처리한다.
- 당첨 취소에 따른 재추첨은 취소로 빈 경품별 자리만 대상으로 하며, 유지되는 당첨자를 다시 선정하지 않는다.
- 재추첨 후보는 원래 이벤트의 유효한 낙첨자다. 기존 당첨자, 당첨 취소자 및 이후 제외가 확정된 사용자는 제거한다. 신규 응모 모집이나 예비 순번 승계는 제공하지 않는다.
- 멤버십 등 원래 응모 자격을 유지하고 이후 확정된 부정행위를 반영한다. 미검토 의심 사용자는 후보에 포함한다.
- 가중치 적용 이벤트는 남은 후보의 최초 추첨 당시 가중치를 유지한다. 미적용 이벤트는 동일 가중치를 유지한다.
- 재추첨 상태는 관리자 실행 시작부터 결과 확인·공개 명단 반영까지 유지하며, 발표된 이벤트는 반영 후 결과 발표 완료로 돌아간다. 최초 발표 전에는 예정된 자동 발표 시각 전 결과를 공개하지 않는 규칙을 유지한다.
- 재추첨 진행 과정과 연출은 일반 사용자에게 공개하지 않는다. 연출은 관리자 화면에만 제공한다. 사용자에게는 관리자 확인 후 갱신된 명단과 본인 결과를 제공한다.

## 가중치 및 중복 당첨

- 응모권 사용 이벤트는 가중치 적용·미적용 방식으로 구분한다.
- 일반 가중치 적용 이벤트는 사용자당 해당 이벤트에서 추가 응모를 포함해 응모권을 누적 최대 5장까지 사용할 수 있다. 1회 요청당 제한이 아니라 이벤트별 사용자 누적 사용 상한이다. 월말 소진용 이벤트의 상한 없음 예외는 [응모권 규칙](ticket.md)을 따른다.
- 가중치 적용 이벤트의 등급 응모권은 실제 차감한 등급별 장수에 장당 가중치를 곱해 합산한다. 브론즈 1, 실버 3, 골드 5를 적용하며, 등급 응모권의 가중치 합계는 `브론즈 차감 장수 × 1 + 실버 차감 장수 × 3 + 골드 차감 장수 × 5`다. 추가 응모도 합산하고 요청 수량이나 거절된 응모는 반영하지 않는다.
- 응모권 사용 수량과 별개로 가중치 값에 추가 상한을 두지 않는다. 등급 응모권 5장을 사용할 때 골드 5장이면 가중치는 25가 된다. 월말 소진용 이벤트는 유효 보유량 내에서 사용한 등급별 가중치를 별도 상한 없이 합산한다. 등급별 장당 가중치 외의 추가 배율은 적용하지 않는다.
- 예: 골드 1장·실버 1장·브론즈 1장을 차감한 경우 실제 사용량은 3장, 추첨 가중치는 9다. 최초 후보 스냅샷에는 실제 장수와 확정 가중치를 구분해 보존하며 재추첨에서는 최초 가중치를 유지한다.
- 가중치 미적용 이벤트는 응모권 1장을 차감해 응모하며 응모자별 추첨 가중치는 1이다.
- 응모권 미사용 이벤트는 이벤트 단위 응모를 기준으로 추첨하며 응모자별 추첨 기회와 가중치는 1이다.
- 이벤트 하나에서 동일 사용자의 중복 당첨을 허용하지 않는다. 같은 경품과 다른 경품 모두 동일하게 적용한다.
- 실제 등수별 당첨자 선정·경품 배정은 1등 → 2등 → 3등 순서로 진행한다. 이미 당첨된 사용자는 다음 등수 추첨에서 제외한다.
- 유효 후보가 전체 당첨 인원보다 적으면 같은 순서로 상위 등수부터 배정하고, 후보가 소진된 뒤 남은 자리는 미선정으로 처리한다.

## 대상 부족 및 결과 관리

- 각 실행의 유효 후보 안에서만 당첨자를 선정한다.
- 경품별 설정 인원을 준수하며, 유지되는 기존 당첨자와 새 당첨자의 합계가 해당 경품의 설정 인원을 초과하지 않는다.
- 최초 추첨에서 유효 후보가 전체 당첨 인원보다 적으면 전원 당첨시키고 남은 자리는 미선정으로 처리한다.
- 재추첨에서 유효 후보가 보충할 자리보다 적으면 가능한 인원만 선정하고 남은 자리는 미선정으로 처리한다.
- 최초 추첨에서 응모자가 없으면 추첨 없이 '응모자 없음'으로 종료·표시한다.
- 최초 추첨에서 전원 제외되면 추첨 없이 '추첨 대상자 없음'으로 종료·표시하고 본인에게 제외 사유를 안내한다.
- 당첨자 목록, 경품 내역, 당첨 순서, 관리자 실행 이력을 관리한다.
- 최초 추첨과 각 재추첨 실행은 동시 요청·처리 중단 후 재시도에도 각각 하나의 결과만 확정한다.
- 이미 확정된 동일 실행을 다시 요청하면 저장된 확정 결과를 반환하며, 다시 선정하거나 결과·당첨 순서를 변경하지 않는다.
- 새로운 재추첨과 동일 실행의 재시도를 구분하고, 동일한 당첨 취소 건의 재시도·동시 요청이 별도 재추첨으로 중복 반영되지 않도록 한다.
- 재추첨으로 최초 추첨이나 이전 재추첨 결과를 덮어쓰지 않고 이력과 출처를 보존한다.

## 결과 발표

- 정상 최초 결과 발표 예정 시각은 응모 마감 시각 + 5분이다. 이벤트 유형과 관계없이 별도 관리자 승인 없이 자동으로 최초 발표를 시작한다. 최초 공개 전 취소·재추첨이 발생한 경우에는 아래 최종 명단 준비·확인 규칙을 따른다.
- 5분 검토 시간에 탐지·예외 처리를 수행하고 발표할 결과를 준비한다. 실제 선정은 1등 → 2등 → 3등 순서로 수행하며, 서버가 확정한 결과를 화면에서 3등 → 2등 → 1등 순서로 발표한다.
- 발표 전 당첨 결과는 비공개로 유지한다.
- 발표 시각과 공개 여부는 서버 기준이다. 화면의 타이머가 끝났다는 이유만으로 미공개 결과를 노출하거나 프론트엔드에서 당첨자를 선정하지 않는다.
- 최초 발표는 재시도·동시 요청에도 한 번만 반영한다. 발표 전에 취소되거나 응모자 없음·추첨 대상자 없음으로 종료된 이벤트는 당첨 발표 대신 해당 종료 상태를 표시한다.
- 발표 후 당첨 취소·재추첨이 발생하면 관리자가 재추첨 결과를 확인한 후 공개 당첨자 명단을 갱신하며, 별도 재발표는 하지 않는다.
- 재추첨 결과가 확정돼도 자동으로 공개 명단에 반영하지 않으며, 관리자 확인 전에는 새 당첨 결과를 비공개로 유지한다.
- 최초 공개 전 당첨 취소·재추첨이 발생하면 관리자 확인까지 끝난 새 결과와 유지되는 기존 결과를 합쳐 최초 명단을 공개한다. 예정 시각까지 재추첨 결과 준비 또는 관리자 확인이 끝나지 않으면 일부 명단을 먼저 공개하지 않고 최초 발표를 지연한다. 준비·확인 완료 후 서버가 최초 공개를 진행하며 예정 시각 전에는 공개하지 않는다. 정상 최초 추첨에 관리자 승인 대기를 추가하지 않는다.
- 최초 추첨·당첨 취소·재추첨 결과와 연결 관계를 보존한다.
- 관리자는 명단의 변경 대상, 변경 전후 정보, 처리자, 시각과 사유를 조회할 수 있어야 한다. 확인자와 실제 공개 명단 갱신 시각도 변경 이력에 남긴다.
- 당첨 취소·명단 변경 이력을 이유로 내부 검토 사유나 다른 사용자의 비공개 정보를 일반 사용자에게 노출하지 않는다.
- 추첨 결과는 백엔드에서 모두 확정하고, 프론트엔드는 확정된 결과를 3등 → 2등 → 1등 순서로 표시한다. 이 순서는 화면 표시 순서이며 실제 당첨자 선정 순서를 의미하지 않는다.
- 마감부터 최초 발표까지 '응모 마감 · 결과 발표까지 MM:SS'와 05:00부터의 카운트다운을 표시한다. 서버의 발표 예정 시각을 기준으로 남은 시간을 계산하며 새로고침·재접속으로 5분을 다시 시작하지 않는다. 내부 검토 사유는 공개하지 않는다.
- 대상 없는 종료 표시와 제외 당사자 안내는 별도로 제공한다.
- 발표 결과에는 이름·전화번호·이메일을 각각 마스킹해 당첨 경품과 함께 표시한다. 닉네임 표시 정책을 대체한다. 구체적인 마스킹 규칙은 담당자가 결정한다.
- 공개 화면과 응답 데이터 모두에 마스킹을 적용한다.
- 본인 화면에는 자신의 당첨 여부와 경품을 명확히 표시한다.

## 보관과 개인정보

- 최초 추첨·재추첨 후보·조건 스냅샷과 결과 이력의 운영상 보관 기간은 이벤트의 마지막 결과 공개 또는 취소 후 5년이다. 재추첨 결과를 공개하면 마지막 공개 시점을 갱신한다. 보관 정책은 추후 수정할 수 있다.
- 이 5년은 서비스 운영 정책이며 전체 추첨 자료에 일괄 적용되는 법정 보존 의무라고 설명하지 않는다.
- 탈퇴 기능은 제공하지 않는다. 탈퇴 기능 유무와 무관하게 개인정보가 불필요해지면 보관 근거에 따라 파기하고, 법령상 보존 의무가 있는 정보는 분리 보관한다. 개인정보 전체를 무조건 5년 보존하는 근거로 운영 정책을 사용하지 않는다.
- 개인정보의 파기·별도 보관과 추첨 근거 보존을 함께 만족할 구체적인 저장 방식은 확정하지 않았다. 질문에서 제안한 익명화·집계 방안 중 하나를 사용자 선택 없이 확정하지 않는다.
- 법령 참고: [개인정보 보호법 제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?ancYnChk=&chrClsCd=010202&lsJoLnkSeq=1020398651), [전자상거래법 시행령 제6조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0006&lsiSeq=269055&urlMode=lsScJoRltInfoR). 거래기록 해당 여부와 적용 근거를 확인해야 하며 추첨 기록 전체에 전자상거래의 5년을 자동 적용하지 않는다.

등급 응모권의 지급·가중치 결정은 [ADR-014](../03-decisions/014-random-ticket-grades.md)을 따른다. 종전 장수 환산 결정은 [ADR-013](../03-decisions/013-linear-drawing-weight.md)에 보존한다. 마스킹 등 담당자 후속 항목은 [미결정·후속 사항](../00-requirements/pending-decisions.md#추첨과-결과-발표)을 따른다.

## 2026-10-05 변경 범위

- 변경 전: 최초 공개 전 취소·재추첨의 확인과 최초 명단 구성은 미확정이었다.
- 변경 후: 유지 당첨자와 확인된 재추첨 결과를 합쳐 최초 공개하고, 준비·확인이 늦으면 발표를 지연한다. 정상 마감 + 5분 자동 최초 발표는 유지한다.
- 실행 사유·처리자 조회는 연결 취소의 근거와 실행 시작·재개 행위를 구분한다. 상세 요청·응답은 [API 초안](../05-api/drawing.md), 내부 저장 방식은 백엔드 문서를 따른다.
