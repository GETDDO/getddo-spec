# 응모권 도메인 규칙

## 지급 및 조회

- 출석, 미션, 게임 보상으로 응모권을 지급한다. 지급 조건의 판정 기준은 [출석 도메인 규칙](attendance.md), [미션 도메인 규칙](mission.md) 및 [게임 도메인 규칙](game.md)을 따른다.
- 기본 출석 보상의 초기 설정은 일일 1장이다. 변경 가능 범위와 적용 시점은 [출석 규칙](attendance.md)을 따른다.
- 출석 보상의 수량은 [출석 규칙](attendance.md)을 따른다. 미션·게임 보상은 등급 응모권 1장으로 지급하며 아래 등급 추첨 규칙을 따른다.
- 게임 보상은 사용자별로 각 게임에서 하루 1회 등급 응모권 1장을 지급한다. 같은 날 서로 다른 게임의 보상은 각각 받을 수 있다.
- 같은 게임의 반복 플레이나 보상 정책 변경으로 동일 보상 기준일의 지급 제한이 초기화되지 않는다.
- 보유 응모권 수와 지급·차감 이력을 조회한다.
- 이력에서 수량, 사유, 발생 시각, 관련 행위를 확인한다.
- 포인트는 사용하지 않고 응모권으로 관리한다.

## 게임·미션 보상의 등급 추첨

- 보상 지급 조건을 충족한 게임·미션 보상 건마다 서버가 아래 확률로 등급 하나를 무작위 결정하고 해당 등급의 응모권 1장을 지급한다.

| 등급 | 획득 확률 | 실제 지급 수량 | 가중치 적용 이벤트의 장당 가중치 |
| --- | --- | --- | --- |
| 브론즈 (`BRONZE`) | 80% | 1장 | 1 |
| 실버 (`SILVER`) | 18% | 1장 | 3 |
| 골드 (`GOLD`) | 2% | 1장 | 5 |

- 골드 1장은 가중치 5인 응모권 1장이며 일반 응모권 5장을 지급하는 의미가 아니다. 실제 장수와 추첨 가중치를 구분한다.
- 획득 확률은 보상 등급의 추첨 확률이며 이벤트 당첨 확률이 아니다. 개별 사용자나 일정 횟수 안에서 등급별 획득 비율을 보장하는 할당량도 아니다.
- 같은 보상 건의 재요청·동시 요청에서는 최초로 확정된 등급과 지급 결과를 반환한다. 등급을 다시 추첨하거나 응모권을 추가 지급하지 않는다.
- 지급 건의 확정 등급을 보존하고 잔액·지급 이력·사용 이력에서 등급별 실제 수량을 구분할 수 있어야 한다. 추첨 가중치는 [추첨 규칙](drawing.md#가중치-및-중복-당첨)을 따른다.
- 이번 변경의 무작위 등급 지급 대상은 게임과 미션이다. 출석 지급분의 등급, 기존 응모권 전환, 반환 시 등급 처리는 [미결정 사항](../00-requirements/pending-decisions.md#등급-응모권)을 확인한다.

## 정합성 및 중복 방지

- 응모권 이력은 수정·삭제 없이 누적 기록한다.
- 정정이 필요하면 원본에 연결된 별도 이력을 추가한다.
- 반환 시 원본 차감 이력에 연결된 반환 이력을 추가하고 잔액과 함께 반영한다.
- 동일 차감 건의 반환 요청이 반복돼도 중복 반환하지 않는다.
- 이력 합계와 현재 보유 응모권 수의 일치를 보장한다.
- 동시 요청에서도 보유량을 초과해 차감할 수 없다.
- 같은 보상 건의 지급 요청이 반복돼도 한 번만 반영한다.

## 사용 범위·유효기간

- 응모권은 공통 응모권이며, 특정 이벤트에 종속되지 않는다.
- 유효한 공통 응모권을 응모권 사용 이벤트의 응모에 차감할 수 있다.
- 일반 지급 응모권은 지급한 KST 기준월까지 유효하고 다음 달 1일 00:00 KST에 만료한다.
- 반환 응모권은 반환한 KST 기준월의 다음 달 말까지 유효하며, 그 다음 달 1일 00:00 KST에 만료한다. 원래 지급·차감한 월을 기준으로 삼지 않는다.
- 예: 9월 일반 지급분은 10월 1일 00:00 KST, 9월 반환분은 11월 1일 00:00 KST에 만료한다. 화면에는 정확한 만료 일시를 표시한다.
- 만료 시점의 잔여 수량만 만료 처리한다. 이미 차감·접수 완료된 응모는 월 경계 후에도 유효하다.
- 응모권 만료 전까지 차감·응모 접수가 함께 확정돼야 한다. 만료 전 요청 도착만으로 만료 후 사용을 허용하지 않는다.
- 보상의 실제 지급 시점과 적용 만료일을 기록하며, 소급 지급 시각을 임의로 적용하지 않는다.
- 응모권 상태에 '만료'를 포함한다.
- 만료도 이력으로 기록해 이력 합계와 잔액의 일치를 유지한다.

## 응모권 경제·운영

- 추첨 대상에서 제외된 사용자의 해당 이벤트 응모에 차감한 응모권을 반환한다.
- 관리자의 응모권 수동 지급·회수 기능은 이번 버전에서 구현하지 않는다.
- 일반 가중치 적용 이벤트의 응모권 사용 상한은 사용자당 이벤트별 누적 5장이다. 추가 응모도 이 상한에 포함한다.
- 월말에는 응모권 차감 수량 상한이 없는 이벤트를 열어 잔여 응모권의 사용 기회를 제공한다. 이 월말 소진용 이벤트는 일반 이벤트의 누적 5장 상한에서 제외한다. 유효 보유 수량 내에서만 사용할 수 있다.
- 응모권의 유효기간은 월별로 구분하며, 별도의 차감 순서는 두지 않는다.
- 이벤트 취소와 반환은 함께 완료한다. 일시 중단만으로 반환하지 않으며 [이벤트 규칙](event.md)을 따른다.

## 부정 획득 응모권 회수

- 관리자는 부정 획득이 확인된 응모권을 회수할 수 있다.
- 부정 지급 의심만으로 회수하지 않는다. 관리자가 이력과 근거를 검토하고 부정 획득을 확인한 후 회수를 결정한다.
- 한 검토 건에서 동일 사용자의 여러 지급 건을 회수 대상으로 지정할 수 있으며, 지급 건별 회수 대상 수량을 기록한다.
- 회수 결정과 실제 회수 결과를 구분한다. 현재 회수할 수 없는 지급분도 원본 지급 건과 회수 대상 수량을 보존하며, 실제 회수는 근거가 된 검토 결정과 연결한다.
- 이벤트 제외 사실만으로 정상 지급된 응모권을 부정 획득분으로 회수하지 않는다. 다른 정상 지급분을 대신 차감하지 않는다.
- 같은 지급 건이 여러 검토에 포함돼도 회수 대상 수량을 단순 합산하지 않고 기존 결정·회수·만료 이력을 확인한다.
- 확정 판단을 변경할 때 기존 판단과 실제 회수 이력을 보존한다.
- 응모권 잔액을 직접 덮어쓰지 않고, 원본 지급 이력에 연결된 회수 이력을 추가한다.
- 회수 시 대상 사용자, 원본 지급 건, 회수 수량, 사유, 처리자, 처리 시각을 기록한다.
- 같은 지급 건에서 이미 회수한 수량을 다시 회수하지 않는다.
- 이미 만료되거나 회수된 수량은 중복 차감하지 않으며, 잔액을 음수로 만들지 않는다.
- 부정 획득분이 이미 응모에 차감됐다면 해당 응모를 검토한다.
- 제외 처리로 반환되는 부정 획득분은 반환과 회수를 같은 트랜잭션으로 처리해 중간 재사용을 막는다.
- 당첨 후 부정이 확인되면 당첨 취소·재추첨 정책을 적용한다.
- 사용자에게 회수 수량과 사유를 알린다.
- 임의 지급·잔액 수정은 제공하지 않고, 부정 획득분 회수만 허용한다.

일반 지급분과 반환분의 만료일이 다르므로 지급 건별 잔여 수량·만료일과 차감 출처를 보존한다. 별도의 차감 우선순위는 이번 결정으로 추가하지 않는다.

## 2026-10-06 변경 범위

- 변경 전: 게임은 일반 응모권 1장, 미션은 설정된 수량을 지급했다. 가중치 적용 이벤트에서는 차감한 장수 자체를 가중치로 사용했다.
- 변경 후: 게임·미션 보상은 위 확률표에 따라 등급 응모권 1장을 지급한다. 등급별 가중치를 실제 장수와 구분한다.
- 일반 이벤트 누적 사용 상한 5장, 게임별 일일 지급 제한, 미션별 1회 제한과 기존 만료 시각은 이번 변경으로 바꾸지 않는다. 미결정 등급 처리와 전환 범위는 별도로 확정한다.
- 결정 기록: [ADR-014](../03-decisions/014-random-ticket-grades.md).
