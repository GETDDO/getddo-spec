# 2026-10-15 관리자 사용자 조회 계약 준비

- 상태: 검토 대기 · Codex 초안 · 담당자 확인 전
- 목적: C 담당 AO01/AO02의 응답 필드 선택을 기록하고 나머지 공개 계약을 구현 전에 확인한다.

## 수행 내용과 확인된 사실

- 요구사항·scope의 사용자 조회 전용 원칙, 사용자 API 초안, BE User/UserEntity/Repository와 FE 가상 사용자 관리 화면을 대조했다.
- 사용자에게 기본 운영 정보 / 초안 전체 / 담당자 협의의 세 선택지를 제시했고, 사용자는 기본 운영 정보 7개를 선택했다(2026-10-15, 확인자 사용자 전민규).
- 선택된 필드는 id,name,role,status,membership,createdAt,updatedAt다. 관리자 응답에서 연락처·정지 정보는 제외한다. [사용자 API](../05-api/user.md)의 필드 표와 선택 근거에 반영했다.
- 필드 선택은 검색·페이지·권한·업무 오류 전체 채택이 아니다. 관련 제안을 확인 대기 상태로 준비한 뒤, 사용자가 별도 질문에 제안대로 확정하고 spec main 게시·Jira 작업 생성·구현을 승인했다.
- 기존 FE는 `/virtual-users`와 가상 사용자 목록을 사용한다. AO01/AO02의 관리자 검색·상세와 같은 API로 취급하지 않았다.
- GD-62를 실제 조회했으며 C 담당 에픽이다. 관리자 사용자 조회의 별도 작업 제목·범위·완료 조건을 준비했다. 승인 시점에는 새 Jira 이슈·브랜치를 아직 만들지 않았다.

## 다음 할 일과 미결정

- 확인된 AO01/AO02 상세 계약을 게시하고 중복 작업 여부를 확인한 뒤 GD-62 하위 작업을 생성한다.
- 확인 후 C의 새 읽기 기능을 구현하고 활성 관리자·필터 조합·이름 특수문자·안정 정렬·없는 상세·공개 필드·조회 무변경을 검증한다.
- A 담당 기존 사용자 모델·인증·권한 기능은 확인 없이 수정하지 않는다. 실제 FE 수정·연동과 구현 테스트를 구분한다.
- 이 기록이나 확인 대기 제안은 미채택 조건을 확정 정책으로 만드는 근거가 아니다.
