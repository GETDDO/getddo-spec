## 목적

이 대화에서 사용자가 승인한 최초 추첨 재개 경로·입력·권한·응답 상태를 공용 API 문서에 반영하고, 다른 추첨 API 초안과 구분한다.

## 한 일

- 원격 main a66a157과 변경 없는 로컬 상태를 재확인했다.
- [추첨 API의 최초 재개 절](../05-api/drawing.md#최초-추첨-실패-재개--gd-87-일부-계약-확정)에 승인된 부분만 작성했다. AD01~AD09 전체·DTO 전체 필드·업무 ID를 임의로 확정하지 않았다.
- 새 실행 생성과 실패한 기존 최초 실행 재개를 구분하고 GD-138의 AD05·AD09 책임을 유지했다.

## 확인된 내용

- 사용자가 활성 관리자·INITIAL만 허용하는 POST /api/v1/admin/draws/{runId}/resume, 본문 없음, 확정 200/미확정 202/충돌 409 계약을 승인했다. 유효 사용자 문맥의 비관리자는 403이다.
- 확정 결과와 고정 스냅샷을 보존하고 진행 중이면 현재 상태를 반환한다.
- 정상 최초 추첨에 관리자 승인 대기를 추가하거나 재추첨 생성·공개 정책을 변경한 것이 아니다.

## 다음 할 일

- 프론트엔드의 실패 상태 조회·재개 연동 확인.
- backend GD-87 실제 구현·검증 결과와 GD-138 연결 확인.

- AD01~AD09 상세 계약·관리자 결과 DTO 전체를 이번 승인만으로 확정하지 않는다.
- 최초 문서 작성 뒤 사용자가 기능별 커밋과 PR 생성을 요청했다. spec은 이 저장소의 AGENTS.md에 따라 별도 PR 없이 main에서 커밋·push한다.
