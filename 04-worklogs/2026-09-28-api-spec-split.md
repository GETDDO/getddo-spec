## 목적

단일 파일로 작성된 API 초안을 도메인별 공용 계약으로 배치하고, DB 및 구현 검토는 백엔드 저장소에서 관리한다.

## 한 일

- Downloads의 `api-specification.md`에서 API ID 80개를 공통 문서와 12개 도메인 파일로 분리했다.
- 공개 요청·응답에 필요한 내용은 `05-api/`에 두고 DB 대응, 내부 처리, 구현 검증 내용은 백엔드 `docs/`로 분리했다.
- 원본의 결정 질문 표는 복사하지 않고 각 파일에서 관련 기준 문서를 연결했다.

## 확인된 내용

- 이 문서들은 담당자 확인 전 API 제안이다. 확정 정책은 [요구사항](../00-requirements/functional-requirements.md)과 [도메인 규칙](../02-domain/README.md)을 따른다.
- 응모 거절 재시도는 기존 4xx·오류 코드, 검토 목록은 `detectedAt DESC, id DESC`, 월말 소진용 이벤트 식별은 `TICKET`·가중치 적용·상한 null 조합으로 반영했다.
