# 추첨 사용자 조회 계약과 후속 범위 반영

- 날짜: 2026-10-14
- 작성: Codex — 담당자 확인 전
- 상태: 검토 대기
- 관련 작업: GD-86·GD-131·GD-140

## 목적

사용자가 선택한 사용자 결과 조회 계약과 이번 제외 범위를 공용 명세에 반영한다. 자동 실행 주기·조회 인덱스 등 백엔드 기술 계획은 백엔드 ADR에서 관리한다.

## 수행 내용

- [추첨 규칙](../02-domain/drawing.md#결과-발표)에 개인정보 표시 규칙을 반영했다.
- [사용자 결과 조회](../05-api/drawing.md#사용자-결과-조회)의 E08·E09 초안 채택을 기록하고 이메일 응답 필드를 제외했다.
- [구현 범위](../00-requirements/scope.md#사용자-추첨-결과-조회--2026-10-14-범위-확인)와 [미결정 목록](../00-requirements/pending-decisions.md#추첨과-결과-발표)에 이번 제외·결정 완료 항목을 맞췄다.

## 확인된 사실과 경계

- 발표 후 취소·재추첨을 운영에서 사용하지 않는다는 사용자 전제로 해당 사용자 중간 표시는 이번 구현에서 제외한다. 기존 관리자 정책·API를 삭제하거나 발표 후 호출을 금지하도록 바꾼 것이 아니다.
- 기존 API로 해당 상황을 만들 수 있으므로 운영에서 사용하기 전에 사용자 표시 계약을 보완해야 한다.
- 발표 전 확인·공개 지연·미확인 결과 비노출·실제 공개 버전 기준은 유지한다.
- 기존 spec 로컬 변경은 보존했다. 관련 문서의 원격 변경 여부를 확인했으며 원격 main 3c0856b를 검토 기준으로 사용했다.
- 이메일 제외와 마스킹은 프론트엔드 응답 처리에 반영해야 한다. 이번 기록은 코드 구현·운영 적용 완료를 의미하지 않는다.

## 다음 할 일

문서 확인 후 관련 구현과 프론트엔드 계약을 맞춘다. 나머지 공용 미결정 정책을 임의 확정하지 않는다. 테스트·빌드·push·Jira 변경은 이번 문서 작업에서 하지 않는다.

## 추가 변경: 관리자 수동 최초 공개

자동 추첨은 유지하되 관리자 확인과 수동 최초 공개를 분리했다. 고정 발표 예정 시각·카운트다운·자동 공개 재호출을 제거하고 발표 대기를 사용한다. 요구사항·이벤트/추첨 도메인·API·미결정 목록을 맞췄다. [ADR-022](../03-decisions/022-manual-initial-publication.md)는 제안으로 작성했으며 정책 확인과 ADR 문서 검토를 구분한다. 새 후속 구현은 GD-199에서 진행한다. 기존 취소·재추첨·알림 구현은 변경하지 않았고 알림 담당 문서의 자동 발표 문구는 담당자 동기화가 남아 있다. Jira 계획과 개인 HTML을 갱신하며, 코드·테스트·커밋·push는 이번 범위에 포함하지 않는다.
