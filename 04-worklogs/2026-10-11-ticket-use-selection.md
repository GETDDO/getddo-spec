# 작업 기록: 응모 시 응모권 차감 선택 방식 확정

- 작성일: 2026-10-11
- 관련 이슈 / PR: GD-133 / 백엔드 PR 45
- 상태: 검토 대기
- 영향 범위: 공통 / 프론트엔드 / 백엔드

## 목적

응모권 차감·반환 서비스(GD-133)를 구현하면서, 미결정이던 "사용자가 차감 등급별 장수를 선택할지, 서버가 차감 순서를 정할지"를 응모권 담당자(윤태형)의 결정으로 확정한다.

## 한 일

- [응모권 규칙](../02-domain/ticket.md#응모권-경제운영)에서 "별도의 차감 순서는 두지 않는다"를 지우고, 사용자가 등급별로 쓸 장수를 고르며 같은 등급 안에서는 만료가 이른 응모권부터 차감한다는 규칙을 썼다.
- [미결정 사항](../00-requirements/pending-decisions.md#등급-응모권)의 차감 선택 항목을 확정으로 옮기고, 요청·응답 필드 형태만 미결정으로 남겼다.
- [응모권 API](../05-api/ticket.md)의 "차감 등급 선택 계약은 확정하지 않는다"를 확정된 선택 방식을 가리키도록 고쳤다.

## 변경 전후

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 차감 선택 | 사용자가 고를지 서버가 정할지 미결정 | 사용자가 등급별로 쓸 장수를 고른다 |
| 상한 | 정해지지 않음 | 등급마다 현재 사용 가능한 장수 |
| 같은 등급 안의 순서 | 별도의 차감 순서를 두지 않음 | 만료가 이른 응모권부터 차감 |
| 요청·응답 필드 | 미결정 | 미결정(프론트엔드와 협의) |

## 확인된 내용

- 보유 조회(T01)의 `countByGrade`가 이미 등급별 사용 가능 장수를 주므로 사용자는 그 안에서 고른다. `holdings`는 등급과 만료 시각별 묶음이라 곧 만료되는 장수를 화면에 보여 줄 수 있다.
- 같은 달에 지급된 응모권은 등급과 관계없이 같은 시각에 만료하므로, 만료 순서가 갈리는 것은 반환분(반환한 달의 다다음 달 1일 만료)이 섞인 경우다. 늦게 만료하는 응모권을 남기는 편이 항상 사용자에게 유리하고 추첨 가중치는 등급으로만 정해지므로 어느 응모권을 쓰는지는 선택에 영향을 주지 않는다.
- 추첨 문서는 "실제 차감한 등급별 장수에 장당 가중치를 곱한다"고 이미 쓰고 있어 수정하지 않았다.
- 반환 응모권의 등급 보존 방식은 이번에 정하지 않았다. 백엔드 구현은 같은 응모권이 등급 그대로 돌아오는 임시 구현이다.

## 다음 할 일

- [ ] 프론트엔드와 응모 요청·응답 필드 형태를 협의한다. 등급별 장수를 고르는 화면이 필요하다.
- [ ] 석종수 담당: 반환된 사용 이력을 추첨 후보 스냅샷에서 어떻게 처리할지 확인한다. 현재 스냅샷 읽기는 사용 이력을 모두 읽고 반환 여부를 구분하지 않는 것으로 보인다.
- [ ] 반환 응모권의 등급 보존 방식과 반환분 유효기간 정책을 결정한다.

## 미결정·차단 사항

- 응모 요청·응답 필드 형태.
- 반환 응모권의 등급 보존 방식.
