# 작업 기록: 출석 현황·월별 조회(AT01·AT03) 계산 규칙과 보상 구분 필드 반영

- 작성일: 2026-10-10
- 관련 이슈 / PR: GD-128 / 백엔드 PR 42 / 스펙 PR 8
- 상태: 검토 대기
- 영향 범위: 공통 / 프론트엔드 / 백엔드

## 목적

출석 화면에 필요한 AT01(오늘 출석 현황)과 AT03(월별 출석)을 백엔드에서 구현하면서 스펙에 없던 계산 규칙을 정하고, 출석 보상 응답에 일일 보상과 단계 보상을 구분하는 필드를 더한다.

## 한 일

- [출석 API](../05-api/attendance.md)에 AT01·AT03 계산 규칙을 추가했다.
- `RewardReceipt`에 `rewardType`(DAILY/STREAK)과 `milestoneDays`를 추가했다.

## 변경 전후

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| AT01·AT03 계산 규칙 | 필드만 있고 계산 규칙이 없었다 | 연속 일수, 단계 묶음 선택, 수령 여부와 시각, 정책 없음 처리, `month` 검증을 명시 |
| `RewardReceipt` | `claimId`, `ticketCount`, `grantedAt?`, `expiresAt?` | `rewardType`, `milestoneDays?` 추가 |

## 확인된 내용

- 규칙은 담당자(윤태형)가 2026-10-04에 정한 계산 규칙을 따랐고, 백엔드 PR 42에서 구현·테스트했다.
- `rewardType`·`milestoneDays`는 백엔드 도메인과 DB(`attendance_reward_claims.reward_type`, `milestone_days`)에 이미 있는 값이라 ERD 변경은 없다. 응답에 필드를 추가하는 변경이라 기존 클라이언트와 호환된다.
- 출석 응답의 등급(`grade`) 표시 여부는 이번에 정하지 않았다. 출석은 항상 브론즈다.

## 다음 할 일

## 미결정·차단 사항

- 자정 경계에서 서로 다른 업무일 요청이 역순으로 처리될 때 연속 일수와 단계 보상이 어긋날 수 있는 쓰기 경로 문제를 백엔드 후속 작업(GD-129)에서 다룬다. 이 문서의 규칙은 정상 순서의 처리를 기준으로 한다.
