# 2026-09-29 추첨 발표 지연 정책

- 작성: Codex (담당자 확인 전)
- 상태: 검토 대기
- 관련 이슈: GD-36

## 목적

마감 + 5분 자동 최초 발표에 실패했을 때의 처리 방안을 검토한다. 아래 작성안은 확정된 정책이 아니다.

## 수행 내용

- 발표 지연 시 안내·자동 공개·자동 취소 금지 작성안은 확정된 결정이 없어 도메인·API 문서에서 제거하고 미결정 사항으로 되돌렸다.
- 아래 항목은 최초 작성 경과이며 현행 확정 정책으로 사용하지 않는다.
- [추첨 도메인 규칙](../02-domain/drawing.md#결과-발표)에 발표 지연 중 비공개·안내, 복구 후 자동 공개, 실패만으로 자동 취소하지 않는 기준을 추가했다.
- [추첨·결과 API 초안](../05-api/drawing.md#공개-결과와-본인-결과)에 기존 `WAITING`·`PENDING`을 유지하고 “결과 확인 중”을 표시하는 방법을 기록했다.
- [미결정 사항](../00-requirements/pending-decisions.md#추첨과-결과-발표)의 예외 처리 항목을 갱신했다.

## 확인된 사실

- `getddo-spec/main` 원격 해시와 로컬 해시가 일치했다. 백엔드 작업 브랜치는 추적 브랜치가 없어 pull하지 않았다.
- 설계 문서 작업이므로 애플리케이션 구현·테스트·빌드는 수행하지 않았다.

## 다음 할 일과 미결정 사항

- 백엔드 D 담당과 이벤트 잠금·차감 수량 계약을 확인한다.
- 프론트엔드 담당과 발표 지연 표시를 확인한다.
- 백엔드에서 오류 분류, 운영자 재개 경로와 자동 재시도 간격을 구체화한다.
