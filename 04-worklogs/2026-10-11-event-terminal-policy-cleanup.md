# 작업 기록: 이벤트 종료 상태의 이전 정책 문구 정리

- 작성일: 2026-10-11
- 관련 이슈 / PR: GD-59 / 이번 작업에서 PR 생성하지 않음
- 상태: 검토 대기 — Codex 작성 초안, 담당자 확인 전
- 영향 범위: 공통 / 프론트엔드 / 백엔드

## 목적

사용자 요청에 따라 이벤트 규칙에 남은 이전 종료 상태 문구를 삭제하고, 지급 전 차단·추첨 제외 폐지 정책과 충돌하는 잔여 항목을 확인한다.

## 한 일

- 변경 전: 이벤트 규칙의 상태 관리에서 '응모자 없음'과 '추첨 대상자 없음' 종료 상태를 구분하도록 요구했다.
- 변경 후: 해당 문장을 삭제했다. 응모자 없음 종료와 신규 전원 제외 종료 미사용은 [추첨 규칙](../02-domain/drawing.md#대상-부족-및-결과-관리)을 따른다.
- 요구사항·범위·현재 도메인 규칙·API 문서, ADR의 대체 기록과 BE 이벤트·추첨 코드·테스트·DB 설명·담당 분장 문서를 검색하고 실제 처리 흐름을 확인했다.

## 확인된 내용

- 기준 결정은 [ADR-018](../03-decisions/018-pre-issuance-abuse-blocking-and-no-draw-exclusion.md), [요구사항](../00-requirements/functional-requirements.md), [추첨 규칙](../02-domain/drawing.md)이다. 정상 접수된 응모를 어뷰징 차단 기록으로 추첨에서 제외하지 않는다.
- spec의 다른 현재 정책 문서에서는 같은 전원 제외 종료를 신규 기능으로 요구하는 문장을 추가로 찾지 못했다. 과거 ADR의 변경 전 내용과 작업 기록은 이력으로 보존한다.
- BE 이벤트 조회의 `EventStatus.NO_ELIGIBLE_ENTRANTS`와 전체 상태 필터 테스트 항목은 남아 있다. 테스트는 해당 이벤트를 직접 만들어 조회·건수를 확인하며 과거 데이터 조회 전용이라는 설명이 없다. 실제 DB에 해당 상태의 행이 존재하는지는 확인하지 않았다.
- BE `docs/03-database/schema.dbml`의 `event_participants` 설명에는 삭제된 추첨 제외 상태·사유·시각의 대체 표현을 보완해야 한다는 문구가 남아 있다.
- BE `docs/01-conventions/backend-feature-assignments.md`에는 참여 허용·추첨 제외 판단과 제외 알림 연동이 남아 있다. 중단·재개 역할도 현재 이벤트 기능 제외 정책과 달리 남아 있다.
- 최신 BE 추첨 준비 구현은 제외 저장소 없이 정상 응모 전원을 후보로 확정하고, 응모자가 없으면 `NO_ENTRIES`로 종료한다. `NO_CANDIDATES`는 새 입력 확정에서 거절하며 과거 실행 조회와 재요청 보존을 명시적으로 검증한다. 이 코드·테스트를 이전 정책의 신규 생성 로직과 구분했다.
- `ENTRY_EXCLUDED` 알림 유형은 알림 API·BE enum·DB 정의에 남아 있다. [후속 확인](../00-requirements/pending-decisions.md#지급-전-차단-전환의-후속-확인)에 담당 영역 검토 대상으로 명시돼 있으며 이번 작업에서 수정하지 않았다.

## 다음 할 일

- [ ] 이벤트 조회의 과거 종료 상태 호환 처리 범위를 정하고 enum·테스트를 정리한다.
- [ ] BE ERD 설명과 담당 분장 문서를 현재 정책에 맞춘다.
- [ ] 알림 담당자가 제외 알림 유형의 신규 발생·과거 조회 처리를 검토한다.

## 미결정·차단 사항

과거 상태 조회 호환성은 기존 명세의 별도 검토 대상이다. 실제 저장 데이터의 존재를 전제로 단정하지 않았으며 기존 Flyway와 과거 이력을 수정하지 않았다. 당첨 취소·재추첨은 기존 정책을 유지하므로 이번 추첨 제외 폐지와 함께 제거하지 않는다.
