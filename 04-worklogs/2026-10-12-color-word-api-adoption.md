# 글자색깔 맞추기 연동 계약 채택 반영

- 상태: 검토 대기
- 사용자 확인: “일단 명세서대로 하고 나머지는 너가 추천한대로 해줄래?”
- 목적: 확정된 명세를 우선하면서 직전 초안의 추천 방식을 구현 기준으로 반영한다.

## 변경 전후

- 변경 전: 플레이 점수·목숨·제한 시간 규칙만 확정됐고, [연동 문서](../05-api/game-color-word-draft.md)의 전송·운영 방식은 제안이었다.
- 변경 후: 색깔 게임의 서버 발급 문제 생성 기준·일괄 답변 제출·G03/G04·시간 경계·일시정지·중도 종료·KST 보상일·재시도를 사용자 채택으로 기록했다.
- 공용 정책은 [게임 도메인](../02-domain/game.md)에, 전송 세부는 [색깔 게임 연동 계약](../05-api/game-color-word-draft.md)에 두고 [게임 API](../05-api/game.md)와 [후속 사항](../00-requirements/pending-decisions.md#게임)을 연결했다.
- 이 작업 기록의 검토 대기 상태는 기록 자체의 검토 상태다. 사용자가 확인한 정책을 다시 미확정으로 돌리는 의미가 아니다.

## 영향과 범위

- 프론트: 자체 난수·최종 점수 전송을 서버 발급 기준과 답변 기록으로 연결하고 실제 시간 누적·경계·재시도를 반영해야 한다.
- 백엔드: 동일 생성 알고리즘, 서버 점수 판정, 최초 결과 보존과 기존 응모권 지급 계약을 구현한다.
- 클라이언트 입력 기록이 실제 사람의 플레이를 증명하지 못한다는 한계는 유지한다. 어뷰징 차단 기준이나 타꼬런 계약을 일괄 확정하지 않는다.
- GD-153·GD-157에 확인 범위를 기록하되 전체 설계·코드 구현 완료로 처리하지 않는다.

## 검증 및 후속

- JSON 예제·상대 링크·diff를 검증한다. 애플리케이션 코드 변경·실행 테스트는 이번 계약 정리 범위에 포함하지 않는다.
- 다음 구현에서 입력/보존 한도·공개 오류 및 생성기 공통 테스트를 구체화하고 실제 프론트 반영을 확인한다.
- 계약과 작업 기록은 로컬 반영 상태이며 커밋·push 전이다.
