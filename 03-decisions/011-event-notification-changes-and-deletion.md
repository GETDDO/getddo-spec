# ADR-011: 일정 앞당김의 추가 알림 제외 및 이벤트 삭제 시 알림 제거

- 상태: 대체됨 — 시작 시각 앞당김 관련 정책은 [ADR-012](012-event-registration-and-editing-rules.md)의 앞당김 금지로 대체한다. 이벤트 삭제 시 알림 전체 제거 정책은 사용자 정정에 따라 철회했다. 아래는 당시 결정 기록이며 현행 기준은 ADR-012와 도메인 문서를 따른다.
- 작성자 / 날짜: 사용자 정책 결정에 따라 Codex 정리 / 2026-09-23
- 검토자: 사용자 직접 결정 반영, 별도 팀 검토 이력 없음
- 관련 작업 기록 / PR: [작업 기록](../04-worklogs/2026-09-23-event-notification-policy.md), PR 미생성
- 대체한 ADR: [ADR-008](008-finalized-service-policies.md)의 일정 변경 알림 중 시작 시각을 앞당기는 경우를 부분 대체한다.

## 배경

이벤트 CRUD 검토에서 시작 10분 전 알림 시각을 지난 일정 변경과 이벤트 삭제 후 기존 알림 처리가 확인 사항으로 나왔다. 사용자는 일정이 앞당겨져도 추가 알림을 발송하지 않고, 이벤트 삭제 시 발송된 알림까지 모두 삭제하도록 정했다.

## 결정과 이유

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 시작 시각 앞당김 | 기존 시작 알림 수신자에게 일정 변경 안내 | 앞당김으로 인한 추가 시작·일정 변경 알림 없음 |
| 앞당김으로 이미 지난 시작 알림 시각 | 보충 발송 기준 없음 | 즉시·추가 보충 발송 없음. 기존 예약은 제거 |
| 이벤트 삭제 | 연결 배너 삭제는 확정, 기존 알림 처리 미명시 | 발송·읽음 여부와 관계없이 연결된 사이트 내 알림 삭제, 미생성 예약 제거 및 재생성 방지 |

사용자의 이번 결정을 반영하며, 기준 정책은 [알림 규칙](../02-domain/notification.md)과 [이벤트 규칙](../02-domain/event.md)에 둔다.

## 검토한 대안

검토에서 즉시 보충 발송, 알림 생략, 등록 제한의 처리 차이를 확인 사항으로 제시했다. 사용자는 일정 앞당김의 추가 발송을 하지 않고, 이벤트 삭제 시 발송된 알림까지 삭제하도록 답했다. 선택 이유는 별도로 전달되지 않았다.

## 영향과 재검토 조건

- 백엔드: 일정 앞당김의 추가 안내를 생성하지 않고, 삭제와 알림 예약·비동기 재시도 처리를 연동해 삭제된 이벤트의 알림이 다시 생기지 않게 한다.
- 프론트엔드·백오피스: 일정 앞당김의 추가 알림 발송을 전제로 안내하지 않으며, 이벤트 삭제 후 사용자 알림함에서도 해당 알림을 제거한다.
- 이벤트 삭제 가능 조건, 일정 앞당김 이외의 변경·취소 안내는 기존 정책을 따른다.
- 사이트 내 알림 삭제와 별개로 감사 로그·모의 발송 이력의 보관·물리 삭제 방식은 이번 결정으로 변경하지 않는다.
