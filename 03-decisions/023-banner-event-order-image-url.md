# ADR-023: 배너의 이벤트 연결·관리 순서·이미지 주소 분리

- 상태: 채택 — 2026-10-15 사용자 상세안 및 공용 게시 승인
- 작성자 / 날짜: Codex / 2026-10-15 KST
- 근거: 사용자가 이벤트 ID·순서1~5·감사 추적, 삭제/취소 사용자 숨김·관리자 보존, 이미지 저장소/공개 주소 분리, 삽입 시 밀기·삭제 시 당기기를 각각 선택했다.

## 결정과 이유

기준은 [배너 규칙](../02-domain/banner.md)이다. 현재 DB URL·1~5 제약과 API 초안 eventId·0이상·createdBy의 차이를 해소한다. 이벤트를 명시적으로 연결하고 관리 순서를 유지하며 저장소 접근 주소와 사용자용 주소를 분리한다. 처리자는 기존 감사 기록을 재사용한다.

[ADR-021](021-manual-banner-deletion.md)의 수동 삭제를 유지하고 사용자 노출 제외를 별도 처리한다. 이벤트 삭제를 막거나 배너를 자동 삭제하지 않는다.

## 검토한 대안

- 기존 URL만 유지: 기존 DB 변경이 적지만 이벤트 추적·연결 검증을 URL 해석에 의존한다. 사용자가 이벤트 ID 연결을 선택했다.
- 겹치는 순서를409로 거절: 구현은 단순하지만 관리자가 빈자리를 따로 골라야 한다. 사용자가 삽입 시 밀기·삭제 시 당기기를 선택했다.
- 삭제/취소 이벤트 배너 계속 노출: 관리자가 정리할 때까지 잘못된 이벤트 링크가 남는다. 사용자가 사용자 숨김·관리자 보존을 선택했다.

## 후속

기존 행 조사·안전한 이전, 실제 MySQL 순서 원자성 검증, A 이미지 연동·FE 연결이 남아 있다. 이미지 형식/용량·업로드 서비스·기존 행 유무를 임의 확정하지 않는다. 저장 방식은 BE 내부 문서에서 관리한다.
