# ADR-005: 출석·미션·게임의 도메인 분리와 보상 조건 확정

## 배경

출석·미션·게임은 응모권 지급을 발생시키는 판정 영역인데 `02-domain/`에 해당 문서가 없었다. 다른 영역은 기능 요구사항에 '무엇을'을 쓰고 도메인 문서에 '어떤 조건에서 어떻게 판정하는가'를 쓰는데, 이 세 영역만 두 번째 층이 비어 있었다. 판정 기준을 기록할 위치가 없어 다음 항목이 미결정으로 남아 있었다.

- 연속 출석은 기능 요구사항의 일회성 미션 표에 '장기 연속 출석'으로 기재돼 있었으나, 같은 절의 '사용자당 이벤트 기간 중 1회만 달성'이라는 정의와 맞지 않았다. 구현 범위에서 보류한 주간 미션 표에도 연속 출석이 있어 범위가 겹쳤다. 적용 일수, 출석 누락 처리, 등록 허용 범위가 모두 미정이었다.
- 브랜드 퀴즈는 '참여 또는 정답 달성'으로 기재돼 판정 기준이 확정되지 않았다.
- 게임 보상 획득에 필요한 플레이 횟수·점수 조건이 미정이라 지급 판정을 정의할 수 없었다.

## 결정과 이유

### 도메인 분리

- 변경 전: 출석·미션·게임 도메인 문서가 없었고, 연속 출석은 일회성 미션 표에 포함돼 있었다.
- 변경 후: `02-domain/attendance.md`, `02-domain/mission.md`, `02-domain/game.md`를 각각 두고 독립 도메인으로 관리한다. 연속 출석은 출석 도메인에, 설문 참여와 브랜드 퀴즈는 미션 도메인에 둔다. 출석과 게임은 미션으로 관리하지 않는다.

연속 출석은 출석 기록으로만 판정할 수 있어, 출석과 떨어뜨리면 판정 근거가 두 문서로 흩어진다. 게임은 완료 여부가 아니라 플레이마다의 결과와 점수를 쌓는 구조라 미션과 데이터 형태가 다르다.

### 연속 출석

- 변경 전: 적용 일수가 미정이었고 출석 누락 처리 기준도 없었다.
- 변경 후: 연속 출석 일수는 매월 1일 0으로 초기화하고, 출석하지 않은 날이 있으면 0으로 돌아간다. 7일·14일·28일 도달 시 각각 응모권 1장·3장·7장을 지급한다. 같은 달에 같은 단계의 보상은 한 번만 지급하며, 상위 단계 달성이 하위 단계 보상을 대체하지 않는다. 사용자당 한 달 최대 11장이다. 월 단위로 초기화하므로 28일을 초과하는 단계는 두지 않는다.

28일을 상한으로 둔 것은 2월을 포함한 모든 달에서 달성할 수 있도록 하기 위해서다.

### 브랜드 퀴즈

- 변경 전: 참여 또는 정답 달성 중 어느 것인지 재확인이 필요했다.
- 변경 후: 제출한 답이 정답인 경우에만 완료로 인정한다. 오답은 완료로 기록하지 않으며 사용자는 다시 답변할 수 있다. 재도전으로 정답을 맞혀도 보상은 한 번만 지급한다.

설문이 '최종 제출 시 완료'로 확정된 상태에서 퀴즈도 제출만으로 인정하면 두 미션의 달성 조건이 같아진다.

### 게임 보상

- 변경 전: 보상 획득에 필요한 플레이 횟수·점수 조건이 미정이었다.
- 변경 후: 서버가 유효로 판정한 플레이가 해당 보상 기준일에 한 번 이상 있으면 보상을 지급한다. 점수나 플레이 횟수에 따른 차등 지급은 하지 않으며 지급 수량은 항상 1장이다.

제공할 게임 종류와 규칙이 확정되지 않아 점수 커트라인을 정할 수 없다. 사용자별·게임별 하루 1장 상한이 이미 지급 남발을 막고 있다.

## 검토한 대안

- **연속 출석을 월별 반복 미션으로 분류**: 기능 요구사항이 연속 출석을 미션 표에 두고 있었으므로, 미션 안에 '월별 반복 미션' 범주를 신설하는 방안을 검토했다. 판정에 출석 기록이 필요해 출석과 떨어뜨리면 근거가 흩어지고, 사용자에게도 출석 보상으로 묶여 보인다는 점에서 채택하지 않았다.
- **출석·미션·게임을 한 문서에 작성**: 세 영역 모두 '행동을 판정해 응모권을 지급한다'는 형태가 같아 한 문서로 두는 방안을 검토했다. 판정 구조가 서로 달라 문서를 나눴다.
- **연속 출석 단계의 반복 수령 허용**: 같은 달에 7일 연속을 여러 번 달성하면 그때마다 지급하는 방안을 검토했다. 7일 출석 후 하루 쉬는 패턴이 한 달 개근보다 많은 보상을 받게 되어, 출석을 유도하려는 기능이 출석을 끊도록 유도한다. 채택하지 않았다.
- **최고 단계만 지급**: 상위 단계 달성 시 하위 단계 보상을 지급하지 않는 방안을 검토했다. 7일·14일 단계가 중간에 실패한 사용자를 위한 보상으로만 남아 단계 구조의 의미가 약해진다. 채택하지 않았다.
- **28일 대신 30일**: 2월에는 달성이 불가능해 매년 한 달은 해당 단계가 성립하지 않는다. 달마다 기준 일수를 다르게 하는 방안도 검토했으나, 앞의 두 단계는 고정 일수이고 마지막만 가변이 되어 규칙이 일관되지 않는다. 채택하지 않았다.
- **게임 보상에 점수 커트라인 적용**: 게임 종류·규칙이 확정된 뒤에만 커트라인을 정할 수 있어 현 시점에는 적용하지 않는다. 보류이며 기각이 아니다.

## 영향과 재검토 조건

- 백엔드: 출석 기록에서 연속 일수를 판정하고, 단계별 지급이 같은 달에 한 번만 반영되도록 보장해야 한다. 퀴즈는 정답 판정 후 지급하며 오답 시 완료 기록을 생성하지 않는다.
- 프론트엔드: 출석 화면에서 연속 출석의 단계별 진행 상태를 표시하고, 미션 목록에는 설문과 퀴즈를 노출한다.
- 백오피스: 출석 정책에서 연속 출석 단계별 달성 일수와 보상 응모권 수를 관리하고, 미션 관리에서 퀴즈 문항과 정답을 관리한다.
- 정답 정보는 사용자에게 제공하는 응답에 포함하지 않는다.
- 게임 보상에 점수 조건을 도입하려면 게임 종류·규칙이 확정된 뒤 이 결정을 다시 검토한다.
- 미션의 소속 범위, 미션별 보상 수량, 퀴즈 재도전 횟수 제한은 확정하지 않았으며 [미결정 사항](../02-domain/mission.md)에서 관리한다.
- 게임 보상 기준일의 시간대는 확정하지 않았다. 기본 출석은 00:00 UTC 기준이다.

상세 규칙은 [출석 도메인 규칙](../02-domain/attendance.md), [미션 도메인 규칙](../02-domain/mission.md) 및 [게임 도메인 규칙](../02-domain/game.md)을 따른다.
